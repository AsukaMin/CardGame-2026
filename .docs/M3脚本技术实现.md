## 一、目录归位与文件清单

新增 4 个脚本（Assembly-CSharp，**全局命名空间**——与 UI 框架类一致；窗口/条目本就是"显示"，归 UI 文件夹，不再用 Presentation 命名空间）。位置遵循《单机卡牌游戏-目录结构与资源加载.md》的目录职责（UI = 框架 + 各窗口类）：

| 文件 | 位置 | 角色 | 关键职责 |
|---|---|---|---|
| `BattleWindow.cs` | `Scripts/UI/Windows/` | UIWindow 子类（Fullscreen） | 订阅事实事件全量刷；手势/按钮 → BattleSession 命令；落点判定；交互锁；tip。未来 ResultWindow/TipWindow 同进此文件夹 |
| `CardItemView.cs` / `UnitItemView.cs` | `Scripts/UI/Items/` | 条目视图（运行时挂） | 显示卡面/单位数据、边框随卡型切换（CardItem）；drag 节点 EndDrag 转发窗口；与 Resources/UI 的 CardItem/UnitItem 模板一一配套 |
| `BattleController.cs` | `Scripts/Controller/` | 场景装配件（挂一次） | 读卡表 → 组演示牌组 → 建会话 → 开窗 → 开战；重开一局。未来 M4 流程控制器同进此文件夹 |

另改写 `Unity/Assets/Resources/UI/README.md` 为现行的 UITable 扫描约定（原文还是 SerializeField 拖引用的旧机制）。M1 的 `BattleDebugPresenter` 挪至 `Assets/Editor/`（唯一消费者是冒烟菜单，与 UITableEditor 同住编辑器程序集、去 Presentation 命名空间）——`Scripts/Presentation/`、`Scripts/Editor/` 文件夹均已删除，编辑器工具统一在 `Assets/Editor/`。

数据流（三通道铁律的落地）：

```
逻辑 → UI   GameEventBus 十事件 ──→ BattleWindow.On(E) → AppendLog + RefreshAll()（只读轮询 session）
UI → 逻辑   手势/按钮 ──→ BattleWindow → BattleSession.SummonMonster / PlayEffectCard / Attack / EndTurn
             失败 = InvalidOperationException（中文消息）→ 飘字 + 日志（不走事件下命令）
```

窗口取会话的方式：`BattleController.I.Session`（装配件单例属性，窗口只读）。`BattleDebugPresenter`（M1 的 Debug.Log 占位表现）不再挂载——logText 即肉眼核对位。

## 二、启动与重开（BattleController）

- 时序铁律（策划案§8）：`UIManager.Show("BattleWindow")` **先**（OnShow 订阅 + 全量刷）、`session.Start()` **后**（晚订阅收不到 BattleStarted）。
- 卡表路径与 `Editor/BattleSmokeMenu.CardsJsonPath()` 同款：`Application.dataPath` 上两级（仓库根）拼 `GameData/cards.json`。M3 只保证编辑器播放模式；打包期数据搬运归 Loader 规划（《单机卡牌游戏-目录结构与资源加载》）。
- 种子：Inspector 暴露 `battleSeed`（默认 20261019，与冒烟种子一致），每重开一局 +1（`battleSeed + restartCount`）——同局可复现，连打不重局。
- **重开一局（Restart）**：`UIManager.Hide("BattleWindow")`（OnHide 成对退订，防跨局串台）→ 重建 session → Show → Start。窗口缓存复用不销毁，OnCreate 只走首次，订阅全靠 OnShow/OnHide 配对。
- **M3 临时**：`Update()` 里 R 键 → Restart（Input System：`Keyboard.current.rKey.wasPressedThisFrame`——工程 activeInputHandler=1，旧 Input.GetKey 不可用）。这是 ResultWindow"再来一局"按钮的占位入口，做 ResultWindow 时删掉本方法、按钮改调 `BattleController.I.Restart()` 即可。
- 守卫：场景缺 UIManager / 卡表文件缺失 → Debug.LogError 并中止建局（不带病运行）。

## 三、BattleWindow 刷新链路

### 3.1 订阅清单（OnShow 全部 +=，OnHide 逐条 -=，方法组 `On`）

| 事件 | 日志行（logText） | 附带效果 |
|---|---|---|
| BattleStarted | 开战 —— 双方 HP | 全量刷 |
| TurnStarted | ── 第 N 回合 · 我方/敌方 ── | 全量刷（交互锁随之切换） |
| EnergyChanged | 能量 B → A | 全量刷 |
| CardDrawn / CardPlayed | 抽牌/打出 + 卡名 | 手牌全量重建 + 牌库数 |
| MonsterSummoned / UnitDied | 召唤/死亡 + 名字攻血 | 对应侧场上全量重建 |
| AttackResolved / DamageResolved | 攻击/效果伤害 + 数值（后者带剩余 HP） | HP/盾刷新 |
| BattleEnded | 终局 —— 胜利！/失败… | **临时**：Debug.Log 同步输出（ResultWindow 的位） |

每个回调统一 `AppendLog(一行) + RefreshAll()`——M3 规模小不做增量（策划案§二.3）。订阅完立即全量刷一次（晚开窗错过历史事件）。日志 List 尾插头删，只留 12 行。

**销毁兜底（禁域重载适配）**：工程开了 Enter Play Mode Options 且禁用域重载——静态 `GameEventBus` 跨 Play 会话存活，退出 Play 只销毁窗口、不清静态订阅，下一局首个事件会打到已销毁的窗口（MissingReferenceException，且异常会炸穿 `Session.Start()` 截断开局）。对策：`OnDestroy()` 重复调用 `Unsubscribe()`（List.Remove 幂等，重复退订无害）+ `RefreshAll()` 入口 `this == null` 防御。**凡是订阅静态总线的 MonoBehaviour 都需要这对 OnDestroy 兜底**（可入《事件系统设计》成文约定）。

### 3.2 RefreshAll 读值表（key ↔ 预制体实际扫描 key）

| key | 类型 | 来源 | 逻辑 |
|---|---|---|---|
| turnText | TMP | Turn / Phase / Result | 未开局"准备中…"；终局"战斗结束——胜负"；否则"第 N 回合 · 我方行动/敌方回合" |
| enemyTurnBanner | GO | Phase == EnemyTurn | 显隐开关（全局交互锁的可视化） |
| playerHpText / enemyHpText | TMP | PlayerHp / EnemyHp | 未开局占位"—"（PlayerLeader 在 Start() 前为 null，HP 属性不可读） |
| playerLeaderShieldText | TMP | PlayerLeader.Attributes.CurrentInt(Shield) | **轮询**（盾值不在任何事件载荷——M2 定案，备案 M5-API 缺口清单）；有盾显示"盾 N"，无盾（含未开局）隐藏整个节点 |
| deckCountText / energyText | TMP | DeckCount / Energy | 数字 |
| logText | TMP | 本窗口日志缓存 | 事实日志 + 命令失败提示共用；每行同步 Debug.Log 到 Console（调试用） |
| endTurnButton | Button | Phase/IsBattleOver | `interactable = Phase==PlayerPlay && !IsBattleOver`（置灰=全局锁一部分；手势侧另有静默忽略） |

### 3.3 条目全量重建与摆放

- 手牌（handRoot）/我方场上（playerBoardRoot）/敌方场上（enemyBoardRoot）：清容器 → 逐条 `Instantiate(模板, 容器)` → `AddComponent<视图脚本>` → `Setup(数据, 回调)`。
- **视图脚本运行时挂、模板预制体不放脚本**——遵循预序列化文档"条目根只挂 UITable"的约定。卡面边框（效果卡 card_bg / 怪兽卡 card_bg_creature，Assets/Art/UI素材）**临时写死路径**经 `AssetDatabase.LoadAssetAtPath` 直载（`#if UNITY_EDITOR`：编辑器期专用 API，打包版返回 null、边框保持预制体默认图）——正式版按规划换配置表配路径（Loader 方案），替换点就是 `CardItemView.FrameOf` 一个方法。
- 摆放：无布局系统，`anchoredPosition.x = (index − (count−1)/2) × spacing` 等距横排（手牌 500、场上 520；条目宽约 472）。

## 四、拖拽手势与落点判定（策划案§六）

拖拽 = 纯手势：`drag` 节点（全透明 Image 热区）经 `UIEventListener.EndDrag`（框架约定：Button 点击走 onClick，其余交互走 listener——**没有写任何自定义手势组件**）转发给窗口，窗口在抬起时判定释放点调命令。本体不移动、不跟随（演出归后续表现层）。

| 手势（拖源） | 合法释放目标 | 判定方式 | 命令 |
|---|---|---|---|
| 怪兽卡（CardItem） | 我方场上区 | `RectangleContainsScreenPoint(playerBoardRoot 矩形)`——容器无 Graphic 不参与射线，矩形判定零编辑器依赖 | `SummonMonster(handIndex)` |
| 效果卡（CardItem） | 敌方单位 / 敌方领袖 | 射线（见下） | `PlayEffectCard(handIndex, targetId)` |
| 我方单位（UnitItem） | 敌方单位 / 敌方领袖 | 射线 | `Attack(attackerId, targetId)` |
| endTurnButton 点击 | — | onClick | `EndTurn()` |

射线判定算法（`TryResolveEnemyTarget`）：

1. `EventSystem.current.RaycastAll(eventData, buffer)`，按层次深度从上到下遍历；
2. 跳过拖源自身子树（`IsChildOf(dragSource)`——释放点常落在自己热区上）；
3. 命中物体 `GetComponentInParent<UnitItemView>()` 为敌方 → 该单位；命中在 `enemyLeaderNode`（Button）子树内 → `session.EnemyLeader`；
4. 其余命中（手牌/我方单位/HUD）不合法，**继续往后找**；全列表无合法目标 = 静默取消（释放区外=取消，策划案§六）。

命令失败统一：`try/catch (InvalidOperationException)` → 异常消息已是可读中文（"能量不足：需要 N，现有 M"等）→ `ShowTip`。**tip 通道说明**：框架的 tipLayer 只有层定义、无 API（`UIWindowLayer.Tip` 无消费者）——M3 用 `DotweenHelper.FloatText`（窗口根部纯代码建临时 TMP，上浮淡出自毁）顶替，同时写一行进 logText 留底；未来做 TipWindow 时只换 `ShowTip` 一个方法。

全局交互锁：所有手势入口与按钮先判 `Phase != PlayerPlay || IsBattleOver` → 静默忽略/置灰。敌方回合在 `EndTurn()` 内同步跑完（单线程同帧），锁主要防终局后残余操作与未开局误触。

## 五、控件 key 对照（策划案建议 key ↔ 预制体实际 key）

策划案§四/§五的 key 为"建议"，代码一律用**预制体实际扫描 key**：

| 策划案建议 | 实际（代码取用） | 差异说明 |
|---|---|---|
| playerLeaderHpText | `playerHpText` | 命名不同 |
| enemyLeaderHpText | `enemyHpText` | 命名不同 |
| CardItem `stats`（攻/血合并） | `attack` + `hp` 两个 text | 拆开显示；效果卡两位置空 |
| UnitItem `drag` | `drag`（原节点名 `click`，需改名） | — |
| floatTipRoot | 不设节点 | 飘字直接挂窗口根 |
| （策划案未提）卡面边框 | `bg`（Image） | 怪兽卡 card_bg_creature / 效果卡 card_bg；临时写死路径 AssetDatabase 直载（正式版换配置表，替换点 `CardItemView.FrameOf`） |
| 其余（turnText/banner/盾位/board×2/handRoot/energy/endTurn/log/deckCount/enemyLeaderNode） | 同名 | — |

窗口文案前缀（"我方 HP 30"“牌库 8"等）由代码写入，文本节点只是载体。
