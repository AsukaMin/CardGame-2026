## 一、设计目标与边界

**v3 边界**：`Fusion` 程序集 = 融合（组装）机制域——卡套、部位卡、槽型、装卡、召唤费公式、攻血底数、防御性校验、效果载荷数据形状。**融合发生在战斗外（整备阶段）**：部位卡装入卡套的槽位，装好的整包（MonsterSleeve）交给战斗核心消费。本程序集不含任何战斗行为。

| 维度 | 决策 |
|---|---|
| 纯净性 | 纯 C#，**零 UnityEngine 引用、零程序集引用**——由 `Fusion.asmdef`（`noEngineReferences: true`、空 references）编译期强制 |
| 无 IO | 不碰文件、不碰路径；一切数据经配置 POCO 构造注入（未来由 Loader 导表产出） |
| 可测试性 | 可脱离 Unity 单独编译运行：dotnet NUnitLite 冒烟 + EditMode 测试双通道 |
| 数据驱动 | 效果=POCO 描述符；**新卡=新数据，零代码改动**（补丁方案文档的硬要求） |
| 无随机 | 融合域零随机（原 `Rng` 是战斗域设施，已随战斗移除） |

**程序集与命名**：扁平 namespace `Fusion`（承重墙是 asmdef，namespace 只是门牌）。测试程序集 `Fusion.Tests`（仅 Editor）。

## 三、融合规则（策划案 v2.1 → 代码对照）

| 规则 | 实现要点 |
|---|---|
| 召唤费公式制 | `MonsterSleeve.SummonCost` = `max(0, round(Σ部位费 × 乘数, AwayFromZero) + 定值)`；**先乘算取整再加定值** |
| 攻血归属 | 底数 = Σ身材槽部位攻血（**先求和**）× 卡套 `StatMultiplier`；**卡套本体无任何数值**（布局即身份） |
| 卡槽四型 | `SlotType { Body, OnSummon, Continuous, OnLeave }`；部位卡声明槽型，`Install` 校验槽型匹配且槽为空 |
| 装入 API | `MonsterSleeve.Install(slotIndex, part)`——整备期最小 API；越界 / null / 槽占用 / 槽型不匹配均抛异常 |
| 召唤前置 | `Validate()` 只做**防御性**校验（缺身材槽部位卡抛异常）；合法性由整备阶段保证【约定】 |
| 槽内卡不充能 | 部位卡 `Cost` 写死、召唤时一次付清（"充能档位"是战斗域概念，已随战斗移除） |
| 效果槽载荷 | 效果槽部位卡携带 `Effects`（行为载荷）；身材槽部位卡纯身材（槽型即声明，v2.1 定案） |
| 关键词 | `PartCardConfig.GrantKeywords` 随召唤赋予（词汇表现仅 `Taunt`） |
| 消耗标记 | `Consumable`：单位死亡时随包销毁、战后不回收；回收/销毁清单由未来战斗终局产出 |

**随战斗移除的规则域**（重写时按策划案 v2.1 重新立项，不属本文）：回合循环与阶段机、命令 API 与失败原因、事件广播（原 FusionEvents 十事件）、敌方 AI 与意图、行动点与回复框架、牌区（牌库/手牌/墓地）、单位与场面、伤害/治疗/光环结算、胜负与战利品回收、表现挂起（原 DeferPresentationEvents/EntranceAnimDone）。

## 四、效果载荷形状（数据词汇表）

**一句话**：本程序集只保留"部位卡行为载荷"的**数据形状**——`EffectDef[]`（每组 = 目标选择 + 操作序列）；**解释执行归未来战斗核心**（原 `EffectInterpreter` 已随战斗移除，重写时基于这套词汇重建解释器，或按新设计另行定义词汇）。

**操作目录（EffectOp 七族）**：

| 操作 | 字段 | 备注 |
|---|---|---|
| `DamageOp` | Amount | 对单位或主战者 |
| `HealOp` | Amount | 治疗语义（上限夹紧等细节由执行方定义） |
| `ModifyStatOp` | Stat/Amount/Duration/TurnCount | 攻或血上限修饰 |
| `GrantKeywordOp` | Keyword/Duration/TurnCount | 关键词（现有 Taunt） |
| `GainPointsOp` | Amount | 战斗经济词汇（行动点），保留作载荷形状 |
| `DrawCardsOp` | Count | 战斗经济词汇（抽牌），保留作载荷形状 |
| `ConditionalOp` | Condition/ConditionTarget/Then/Else | 条件分支，可嵌套 |

**目标选择（TargetMode，相对效果来源阵营）**：`Chosen`（命令传入）/ `Self` / `AllEnemyUnits` / `AllFriendlyUnits` / `AllUnits` / `RandomEnemyUnit` / `EnemyHero` / `FriendlyHero` / `Caster`（施法者：部位卡效果=所属单位）。

**条件（ConditionDef）**：`AttributeCompareCondition`——属性（生命/生命上限/攻击）× 运算符（>、≥、<、≤、=、≠）× 比较值（固定数或百分比，基准=比较对象自身生命上限）。求值对象由 `ConditionTarget { Current, Caster, MainTarget }` 决定（默认 Current）。

**时长词汇（ModifierDurationKind）**：`ThisTurn` / `Turns` / `Fusion`——语义（何时过期、何时递减）由未来战斗核心绑定。

**触发时机（由槽型声明，执行归战斗）**：`OnSummon` 召唤时一次、`OnLeave` 死亡时一次、`Continuous` 常驻（光环化）。`EffectDef.PlayAfterAnimation` 是演出标记（"动画后"结算），节拍端口随新战斗再定。

**导表落点**：配置 POCO 即未来 JSON 的形状（无参构造、公开字段，Newtonsoft 直接反序列化）。`Tests/SampleData.cs` 就是活样例，例如部位卡等价于：

```json
{ "Id": 113, "Name": "怨念", "SlotType": "OnLeave", "Cost": 1, "Consumable": true,
  "Effects": [ { "Target": "EnemyHero", "Ops": [ { "Amount": 3 } ] } ] }
```

**补丁纪律提醒**：加卡/改数值=改数据，补丁可行；**新增 EffectOp/Condition 类型或字段=表结构变化，必须出整合包**（板块划分文档的纪律）。

## 六、扩展指南（按改动类型查表）

| 要做什么 | 改哪里 | 改的是代码还是数据 |
|---|---|---|
| 新部位卡 / 新卡套 | 配置 POCO 实例（未来=JSON 表） | **纯数据** |
| 新效果操作（如"召唤衍生物"） | `EffectOp` 子类（形状）+ 未来战斗解释器加分支 | 代码（=整合包） |
| 新条件（如"目标有嘲讽"） | `ConditionDef` 子类 + 未来战斗求值分支 | 代码（=整合包） |
| 接入 JSON 导表 | Loader 读表反序列化成配置 POCO → 局外/整备域组装 `MonsterSleeve` | 代码（Loader 侧） |
| 整备编辑 / 整备 UI | 直接用 `MonsterSleeve.Install / Validate`（战斗核心不参与） | 代码（局外侧） |
| 重写战斗核心 | 新程序集 + 新设计文档；按策划案 v2.1 立项，消费本程序集的卡套/部位卡/效果词汇 | 代码（新域） |

**已知边界与不做**：部位卡费用写死（无充能）；关键词词汇目前仅 Taunt；`GainPointsOp`/`DrawCardsOp` 是战斗经济语义的载荷形状，重写战斗时按需取舍；`Consumable` 只是被数据携带，回收清单产出在战斗终局（归未来战斗）；本程序集无随机、无事件、无命令——行为面只剩 `MonsterSleeve` 的装槽/公式/校验。
