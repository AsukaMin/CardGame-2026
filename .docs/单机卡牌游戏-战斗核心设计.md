# 单机卡牌游戏：战斗核心设计（M1 最小版）

> 状态：v1（2026-10-19，M1 落地轮：回合状态机 + 出牌结算闭环，零 UI）。
> 分工：策划案（仓库外 `CardGame-Doc/战斗/`）定"规则为什么这么定"；技能系统设计定"效果词汇与结算语义"；本文定**战斗核心怎么组织、契约是什么、怎么扩展**。规则依据：《最小战斗规则》（M0 一页纸）+《战斗核心机制策划案》v2.1（不偏离终局方向）。
> 代码位置：`Unity/Assets/Scripts/Battle/Combat/`（Battle 程序集内子目录，namespace `Battle`）；事实事件定义在 `Scripts/GameEvents/BattleEvents.cs`；占位表现在 `Scripts/Presentation/`。
> 标注约定：【实现】=代码已如此；【约定】=使用方须遵守的契约；【预留】=接口已立、内容后补。

## 一、本期范围与两条选型定案

**M1 完成标准（路线图原文）**：纯逻辑下能跑完一场战斗并分出胜负——已由 headless NUnitLite 通道验证（`Battle.Tests` 44/44，含完整自动对局与同种子确定性用例）。

| 选型 | 定案 | 理由 |
|---|---|---|
| 回合状态机载体 | **新写专用回合阶段机**（`TurnFlow.cs`，~100 行） | StateTree（`Scripts/FSM/`）定位是**单位级**行为载体（有实际行为/实体的东西，如敌人 AI），回合流转没有行为实体，不占用【用户定案】。FSM 目录本期零改动 |
| 出牌结算管线 | **接入技能系统 SkillEngine**（宿主接入） | 战斗核心=技能系统的宿主（技能系统设计§9 即为此而写）；路线图军规"新卡效果不得绕过技能系统硬编码"；M2 卡牌数据化零返工 |

**依赖变更**：`Battle.asmdef` 增加 references: `GameEvents`（事实广播用）。技能系统设计 v1 的"Battle 零引用"铁律随之收窄为"**技能系统文件**零项目引用；战斗核心域引用 GameEvents"。

```

Assets/Editor/BattleSmokeMenu.cs    Tools/战斗核心/跑一场冒烟对局（编辑器肉眼验收）
```

**分层与依赖方向**：

```
表现占位（Assembly-CSharp：Presenter/菜单） ──只订阅──▶ GameEvents（事实事件）
                                                        ▲ Send
TurnFlow（阶段机）──驱动──▶ BattleSession（编排门面）────┘
                              │ 实现 ISkillWorld / 持有
                              ▼
                        SkillEngine（技能系统：结算管线/触发/时点）
```

逻辑核心不订阅 GameEventBus（只发送）——无重入风险，天然满足总线"回调内不再 Send"纪律。

## 三、回合流转（TurnFlow）

```
Start → 我方回合 N（出牌阶段） ──EndTurn──▶ 敌方回合 N（召唤→全员攻击） ──▶ 我方回合 N+1 → …
                └──────────────── 任意时刻主战者 HP≤0 ──▶ GameOver ─┘
```

- **命令驱动、同步推进**：`EndTurn()` 返回前敌方回合全部执行完，回到我方回合或终局【约定】。
- 阶段枚举 `BattlePhase { NotStarted, PlayerPlay, EnemyTurn, GameOver }`；"出牌阶段"与该方回合开始重合（M1 唯一子阶段，故无独立 PhaseEntered 事件——需要第二个子阶段时再立）。
- 回合数 `Turn` 进入我方回合时 +1；我方回合 N 与其后敌方回合 N 同数。
- 玩家命令仅 `PlayerPlay` 阶段合法，违例抛 `InvalidOperationException`【约定】。

**回合时点与技能系统接线**（§7.3 宿主调用契约）：

| 时点 | 动作 |
|---|---|
| 每方回合开始 | `engine.Raise(Event.Turn.Started)` → `engine.TickRound()`（Rounds 时长以**方回合**计）→ 能量策略钩子 →（我方）重置攻击机会、抽 1 |
| 每方回合结束 | `engine.ExpirePhase()` |
| 单位召唤 | `engine.Raise(Event.Unit.Summoned)` |
| 单位死亡 | 移场 → 效果/触发器清理 → `engine.Raise(Event.Unit.Died)` |

## 四、命令 API（BattleSession）

```csharp
var session = new BattleSession(setup);   // 一切数据经 BattleSetup 构造注入
session.Start();                          // 造 Leader、抓起手、进入第 1 回合
session.SummonMonster(handIndex);         // 扣面值费、怪兽上场（当回合可攻击）
session.PlayEffectCard(handIndex, targetId);  // 扣费 → engine.Execute(卡.效果组) → 事实广播
session.Attack(attackerUnitId, targetId); // ResolveDamage(…, Combat)，一回合一次
session.EndTurn();                        // 敌方回合同步执行完
// 只读视图：Phase/Turn/Energy/Hand/PlayerBoard/EnemyBoard/PlayerHp/EnemyHp/Result
```

- 目标规则（M1）：效果卡与攻击的目标=**敌方主战者或敌方怪兽**（己方增益目标留给 M2 特殊卡时放开）。
- 效果卡伤害经宿主自定义 op `RecordEffectDamageOp`（世界级触发器订阅 `Event.Damage.Applied`，技能系统§7.6 扩展点）记录，session 在结算收口统一广播——多目标卡/后续 op 也能完整出事实。
- 死亡观察=宿主职责（技能系统设计§12 同款思路）：`CurrentHp≤0` → 整包离场（撤它施加的效果/清它身上的效果/注销触发器）。

## 五、事实事件清单（GameEventBus，struct 即键）

`BattleStarted{PlayerMaxHp,EnemyMaxHp}`、`TurnStarted{Turn,IsPlayerSide}`、`EnergyChanged{Before,After}`、`CardDrawn{CardName}`、`CardPlayed{CardName,TargetId}`、`MonsterSummoned{UnitId,Name,Attack,MaxHp,IsPlayerSide}`、`AttackResolved{AttackerId,AttackerName,TargetId,TargetName,Amount}`（战斗伤害）、`DamageResolved{…,TargetHpAfter}`（效果伤害）、`UnitDied{UnitId,Name}`、`BattleEnded{PlayerWon}`。

【约定】事件=**既成事实**，只在结算完成后的安全点发送；表现层只监听不参与逻辑（本期=Debug.Log 占位）。

## 六、能量（行动点经济最小版）

- 能量为**玩家侧资源**（召唤/出牌共用）；敌方召唤免费【M1 定案，敌方经济后续再议】。
- 回复手段=开局注入策略（策划案 v2.1"框架先行"）：`IEnergyRule { OnTurnStarted / OnPlayerAttackDone / OnCardDiscarded }`——三钩子已立、默认 `FlatPerTurnRule(2)`，弃牌钩子留位（M1 无弃牌命令）。

## 七、敌方 AI 占位（EnemyBrain）

最小规则原文："初期测试就简单写为从预设的怪兽卡列表里召唤一只，然后场上所有怪兽进行一次攻击。"

- 召唤：`BattleSetup.EnemySummons` 依序各回合取一只，耗尽跳过。
- 攻击：场上敌方怪兽各一次；目标=种子随机（玩家主战者与我方在场怪兽等权——让怪兽血量参与意义）。
- M6 意图系统接管时**只换本类**，TurnFlow 编排不动。

## 八、规则定案表（最小规则未写死处；皆可数据调）

| 项 | M1 定案 |
|---|---|
| 攻击频次 | 每怪兽每回合 1 次（`attackedThisTurn` 我方回合开始重置） |
| 召唤失调 | 无——召唤当回合即可攻击 |
| 反击 | 无——攻击是单向结算 |
| 起手/抽牌 | 起手 3 张；每我方回合开始抽 1；牌库空跳过；无手牌上限 |
| 胜负 | 我方 Leader HP≤0=负（先判，同时归零判负）；敌方=胜；即时判定（敌方回合中死亡立即中断后续攻击） |
| 场上数量 | 无上限（策划案已否决席位上限） |
| 怪兽卡形态 | 血攻直给 POCO；M5 融合域接入后由装好的 MonsterSleeve 取代 |
| 效果卡形态 | 单档面值费用；充能档位（低配/完全体）M2+ |
