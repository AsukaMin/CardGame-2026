## 二、T1 三缺口——机制契约

- **卡身份**：`BattleCard.Id` 由 `CardJsonConverter` 从信封注入（卡体字段不进 JSON——往返稳定不破坏）；组装怪兽臂 Id=卡套 id（投影层填）。`SkillContext.CardId → GameplayEvent.CardId`（0=普攻/触发链/周期）。
- **触发器卡**："结界"形态——打出即 `RegisterTrigger(playerLeader, def)`，随本场生灭，注册序=打出序；纯触发卡（effects 空、载荷全在 triggers）加载合法。
- **条件记忆**：`LastDamageKilled` 读 `ctx.LastResult`（最近伤害结算且目标血 ≤0）；治疗覆盖 LastResult 后自然为假。
- **复制卡**：`AddCardToHandOp{CardId,Count}` → `BattleWorld.AddCardToHand` → session 按卡表取卡入手+广播 CardDrawn；`BattleSetup.Cards` 未注入则 op 抛配置错误。

## 三、T3 数据化 + T6 投影——数据流

```
cards.json ─CardCatalog→ ┐
decks.json ─DeckCatalog→ ├─ DemoBattleData.CreateSetup(catalog, deck, enemy, seed) ─→ BattleSetup
enemies.json─EnemyCatalog┘        （牌库=条目序展开，保序——M1 零漂移锚定依赖）        (+.Cards)
parts.json ┐                                                                    │
sleeves.json┴─FusionCatalog→ PrepWindow(整备: MonsterSleeve.Install) ─┐        │
                                            CurrentSleeve → SleeveProjector.Compile
                                            → BattleCard(Summon) 插 deck 顶 → BattleSession
```

- 敌人轮换：`enemies.All[restartCount % Count]`（确定性；选关 M6）。
- 召唤接线（融合文档§五）：GrantTags→标签容器 → 召唤事实 → OnSummon Effects→`Execute(ctx{Source=新单位})` → Continuous Triggers→`RegisterTrigger` → Auras→`Execute(AllAlliedUnits+ApplyEffect)`（**v1 光环目标=我方全体**；按光环单独定目标=未来 schema 扩展，缺口清单立档）→ AfterCombat。
- OnLeave：SweepBoard 序列=移场→**执行 OnLeaveEffects**→效果/触发器清理→UnitDied→广播。
- 光环语义边界：召唤时一次性施加给当时在场单位（后进场吃不到）；死亡 `RemoveEffectsFromSource` 精准撤销；同 def 再施加=叠层。

## 四、UI 侧契约（M3 框架延续）

- **TipWindow**：`Layer=Tip`（过路即走不进栈）；参数 Message/Duration/Color；重复 Show 顶掉上一条；`BattleWindow.ShowTip` 是唯一替换点（M3 留白表指定）。空壳预制体=根节点挂脚本+CanvasGroup+空 UITable（GUID 手配），**不需要编辑器扫描**。
- **PrepWindow**：`Layer=Fullscreen`；流程=首局开始时弹出（EntryWindow 不加按钮、零预制体编辑操作），确认（Validate 通过才可点）/跳过→`BeginBattle`；Restart 不回整备沿用 CurrentSleeve；控件全部代码自建（TipWindow 先例），M6 打磨再转预制体。
- **灰化**：`UnitItemView.SetGray`（CanvasGroup 0.45），`RebuildBoard` 我方条目按 `HasAttackedThisTurn` 传入；命令报错兜底保留。
- **效果卡对己方释放（验收反馈补）**：手势层效果卡先判 `playerBoardRoot`——落在自己怪上=以该怪为释放锚、落空=以玩家领袖为锚；`RequiresEnemyTarget` 的直伤卡拖己方区静默取消；敌方释放不变。会话层见《战斗核心设计》§四目标规则注。
- **技能编辑器（验收反馈补）**：左栏全面板空白可右键（菜单作用于"当前选中文件夹"，点文件夹行选中、绿色高亮，可"回到根目录"）；建卡/建文件夹/重命名/删除后即时重画，`EditorApplication.projectChanged` 同步 Project 窗口的移动/改名；右栏下拉与节点摘要全部中文（`PartCardLabels` 值↔名双表，数据侧仍存英文枚举名——parts.json 合同不动）。

## 五、T5' 技能编辑器（Editor/SkillEditor/，Assembly-CSharp-Editor）

- **PartCardAuthoringAsset.cs**：作者稿 SO（每卡一 .asset，文件名=卡名，`Assets/Editor/SkillCards/Parts/`）+ 纯数据节点 POCO（`[SerializeReference]`：OpNodeData/TargetSwitchNodeData/TriggerConfigNodeData + 边）——**不存 GraphView 对象**（换画布不动数据）。
- **PartCardCompiler.cs**：图→`PartCardConfig` 编译器。映射三规则：目标切换=效果组边界；并行分支=多组（X 左→右）；条件分支=ConditionalOp 递归。常驻双端口（定案）：触发链首=触发配置节点→TriggerDef（**链内单组单目标**——TriggerDef.Effects 合同）；光环链（白名单属性修饰/赋予关键词）→Permanent 光环 def。错误收集带节点定位，导出时汇总中止。
- **SkillGraphView.cs**：GraphView 画布。Unity 6 API 适配：无 `selectionChanged` 事件→`PollSelection()` 轮询（窗口 update 驱动）；无 `ports` 属性→**`Query<Port>()` 直查**（`graphElements` 源码排除 Port，M5 误用 `graphElements.OfType<Port>()` 恒空列表——拖线全端口禁用的根因，2026-10-31 修）；`GraphViewChange` 无 `edgesToRemove`→边删除并入 `elementsToRemove` 处理；选根=`AddToSelection`。**池化事件坑（验收反馈修）**：菜单回调闭包捕获 `ContextualMenuPopulateEvent` 延迟读 `mousePosition` 恒为 (0,0)（右键建节点全落同一点的根因）→ 填充菜单时立即 `contentViewContainer.WorldToLocal` 取值、回调只捕获算好的坐标（右键位置建节点）。连线规则创建时强制：输入单进、禁环（DFS）、常驻双端口白名单。**撤销/重做（2026-10-31 补，次日改 token 载体）**：Unity Undo 快照不捕获 `[SerializeReference]`（直接快照资产时图操作撤销无效——实测），改 `PartCardUndoToken`（string 字段快照：Newtonsoft 序列化卡级字段+Nodes/Edges）走原生 Undo 栈，操作后注册（token 仍是前态）再刷新；`undoRedoPerformed` → Apply 写回资产 → `ReloadFromAsset` 全量重建画布（保视口——Unity 6 `viewTransform` 只读，直接写 `contentViewContainer.transform`；按 Guid 恢复选中）。
- **PartCardTreeView.cs**：左栏资产树（验收反馈重做，参照 XHFrameworkSkillDemo 的 SkillAssetTreeView 模式——资源管理器体验）：TreeView 双层树（文件夹/卡图标+边框+滚动）、单击卡=打开/单击文件夹=选中、双击文件夹=展开收起/双击卡=重命名、右键菜单（空白处右键作用于选中文件夹）、**拖拽移动**（§3.4，禁拖入自身子孙）、新建后自动选中+打开+进入重命名（RenamePopup 主窗居中/回车确认/Esc 取消）；`projectChanged → Reload()` 同步 Project 窗口操作。路径纪律：AssetDatabase 正斜杠 vs `Path.GetDirectoryName` 反斜杠——比较前统一 `Replace('\\','/')`（验收反馈②的根因即此陷阱）。
- **SkillEditorWindow.cs**：三栏窗口（左=PartCardTreeView；中=画布+右键建节点分层菜单；右=参数面板）。导出=全库编译→`SkillJson.Serialize`→写 `GameData/parts.json`→`FusionCatalog.Load` 复验；导入=反编译建新卡（已有 id 跳过——作者稿是唯一事实源）+自动布局；保存=切卡前/关窗自动+按钮/Ctrl+S。**撤销跨卡（2026-10-31 补）**：参数面板与图操作统一经 `CommitUndo`（token 注册+快照刷新）；token 记 `CardPath`，撤销作用于另一张卡时自动切回+气泡提示。
- **验收口径**：编辑器改卡→导出→`FusionCatalog` 通过→整备→战斗行为与手写卡一致（手动 Play 清单，归 T7）。
- 编译校验通道：`.zcode/tmp/SkillEditorCompile`（net48 引用 UnityEditor.GraphViewModule 等真实 DLL——0 错误；Unity 内编译归 T7 EditMode）。
