## 二、总体架构（5 文件，全在 `Assets/Editor/SkillEditor/`，Assembly-CSharp-Editor）

| 文件 | 职责 | 依赖 |
|---|---|---|
| `PartCardAuthoringAsset.cs` | 作者稿 SO + 纯数据节点 POCO + `PartCardLabels` 中文标签表 | UnityEngine（零 UnityEditor——可测） |
| `PartCardCompiler.cs` | 图→PartCardConfig 编译器（校验+错误收集）；纯内存零 UnityEditor | Battle、Fusion |
| `SkillGraphView.cs` | GraphView 画布：节点视图/端口/连线规则/图数据同步 | UnityEditor.GraphViewModule |
| `PartCardTreeView.cs` | 左栏资产树（TreeView+重命名弹窗） | UnityEditor.IMGUI.Controls |
| `SkillEditorWindow.cs` | 主窗口：三栏装配/工具栏/参数面板/导出导入/保存时机 | 以上全部 |

**数据流**：

```
作者稿 .asset（唯一事实源，Assets/Editor/SkillCards/Parts/，每卡一文件、文件名=卡名）
   │ SkillGraphView（图 ⇄ 节点数据双向同步）      PartCardTreeView（资产树 ⇄ AssetDatabase）
   ▼ 导出：PartCardCompiler.Compile 全库 → SkillJson.Serialize
GameData/parts.json（编译产物，不手改）──导入（反编译+自动布局）──┘ 已有 id 跳过
   ▼ FusionCatalog.Load（导出后全量复验）→ PrepWindow 整备 → SleeveProjector → 战斗
```

**纪律**：坐标/图结构只活在本层；导出的 JSON 不手改，回编辑器改再导出（M2 纪律延伸）；编辑器层与运行时唯一交互=读写 parts.json。

## 三、作者稿数据模型（PartCardAuthoringAsset）

卡级字段（=技能节点承载，需求文档§5.2）：`CardId / SlotType / Cost / DefaultTarget（技能目标）/ GrantTags（逗号分隔）/ Consumable / Attack / MaxHp（仅 Body）`；图数据：`Nodes: List<PartGraphNode>`（`[SerializeReference]` 多态）+ `Edges: List<PartGraphEdgeData>`。

**节点 POCO（纯数据，不存任何 GraphView 对象——换画布不动数据）**：

| 节点 | 字段要点 |
|---|---|
| `OpNodeData`（操作） | Kind（Damage/Heal/ModifyAttribute/DrawCards/GrantTag/Condition）+ Target（节点目标三选一：ParentPassed/Caster/Chosen）+ 通用数值位（Amount/Attribute/ModOp/Magnitude/Duration/Rounds/Count/Tag）+ 条件位（CondAttribute/CondOp/CondValueType/CondValue/CondSubject） |
| `TargetSwitchNodeData`（选择目标） | TargetMode（TargetMode 枚举名字符串） |
| `TriggerConfigNodeData`（触发配置） | EventTag / SelfOnly / SourceOnly / Once / HasValueFilter+ValueFilterMin |
| 基类 `PartGraphNode` | Guid（连线引用）+ Position（布局坐标） |

**连线 `PartGraphEdgeData{From, To}`**：`From` = 根端口键（`RootPorts`：`root:OnSummon` / `root:OnSummonLate`（动画完成时） / `root:ContinuousTrigger` / `root:ContinuousAura` / `root:OnLeave`，按槽型生成，Body 无端口）或 节点 Guid 或 条件出口（`Guid:yes` / `Guid:no`）；`To` = 节点 Guid（输入单进）。

**中文标签层 `PartCardLabels`**：值↔名双表（槽型/目标/属性/修饰/时长/比较符/比较值/求值对象/事件/节点目标/操作），`Display(values, names, value)` 查表（未知值原样返回）。**数据侧一律存英文枚举名**（parts.json 合同不动），右栏下拉与节点摘要共用本表做显示翻译。

## 四、画布（SkillGraphView）

**节点视图**：`RootNodeView`（标题+摘要 Label+按槽型生成的输出端口，端口 `viewDataKey`=根端口键；槽型改动即重建端口）与 `PartNodeView`（输入单进端口+输出多连端口；条件分支为 是/否 双出口；摘要=关键参数中文一行，随右栏编辑刷新）。右键画布分层菜单建节点（操作×6/选择目标/触发配置，**建在鼠标位置**——节点左上角对齐右键点，pan/zoom 后同样准确）+全览。

**连线规则（创建时强制，`graphViewChanged.edgesToCreate` 逐条校验）**：

| 规则 | 实现 |
|---|---|
| 输入单进 | `GetCompatiblePorts` 过滤已连接的 Input 端口 + Root 无输入 |
| 禁自环/禁成环 | 连线创建时 DFS：从目标节点沿输出可达输出方 → 拒绝 |
| 常驻「触发」链首必须是触发配置节点 | 连线时类型判定 |
| 光环链白名单（只收属性修饰/赋予关键词） | 连线时 Kind 判定 |
| 触发配置节点只能接在常驻「触发」端口后 | 连线时反向判定 |
| 分支内/触发链内禁切目标 | 连线层不拦（图上合法），**编译期报错**（见§六） |

**图数据同步**（全部走 `graphViewChanged`）：`edgesToCreate`（校验通过→写回 Edges）、`elementsToRemove`（**边的删除与节点删除一并在此处理**——Unity 6 无 `edgesToRemove` 字段；删节点连带清理其全部边）、`movedElements`（坐标写回 node.Position）。选根=`ClearSelection+AddToSelection`。

**撤销/重做（v3.2 引入、v3.3 改 token 载体——Unity 原生 Undo 栈 + 字符串快照）**：覆盖创建/删除节点、连/删边、移动（每次拖拽松手=一步）、右栏节点参数与卡级字段编辑。机制：**Unity Undo 快照不捕获 `[SerializeReference]` 托管引用**（实测 6000.3——卡级普通字段可撤销、图内容不可，v3.2 直接快照资产故图操作撤销无效），故快照走 `PartCardUndoToken`（临时 SO）的**普通 string 字段**：`Blob` 恒为上一提交点（=本次操作前）状态串，任何操作完成后 `Undo.RegisterCompleteObjectUndo(token)`（此刻快照到的即前态）→ 刷新 `Blob` 为现态（Newtonsoft 序列化卡级字段+Nodes/Edges，TypeNameHandling.Auto 出多态 $type）；撤销/重做恢复 `Blob` → `undoRedoPerformed` 里 `Apply` 写回资产 → `ReloadFromAsset()` 全量重建画布（保视口+按 Guid 恢复选中）+`SetDirty`。重做态=撤销瞬间捕获的现态串，天然正确；`Blob==lastAppliedBlob` 即外部对象的撤销，忽略。连线先校验后提交（被拒不产生空步）。**跨卡撤销**：token 记 `CardPath`，恢复时目标≠当前卡 → 自动切回+气泡提示（定案 2026-10-31）。边界：左栏文件操作（AssetDatabase 不走 Undo，删除有确认弹窗）、导出/导入、视图态不进撤销。（XH demo 无撤销可参照；文本框逐字符输入=多步撤销，Inspector 同款行为。）

**Unity 6 GraphView API 适配记录**（与旧文档教程差异，排障先看这里）：

| 差异 | 适配 |
|---|---|
| 无 `selectionChanged` 事件 | `PollSelection()` 轮询（窗口 `EditorApplication.update` 驱动，比较 lastSelection 变化才回调） |
| 无 `ports` 属性 | `graphElements.OfType<Port>()` |
| `GraphViewChange` 无 `edgesToRemove` | 边删除并入 `elementsToRemove` 分支 |
| `GraphElement.Select(Vector2,bool)` 签名 | `AddToSelection(node)` |
| `viewTransform` 只读（返回 `ITransform`） | 视口保存/还原直接读写 `contentViewContainer.transform.position/scale` |
| **Undo 快照不捕获 `[SerializeReference]` 托管引用** | 图快照序列化为 string 存 `PartCardUndoToken`（普通字段可捕获）走原生 Undo 栈；`undoRedoPerformed` 里写回资产重建画布（v3.3） |
| **池化事件：菜单回调闭包捕获 `evt` 延迟读字段** | `ContextualMenuPopulateEvent` 分发结束即归还事件池、字段被重置——闭包里延迟读 `evt.mousePosition` 恒为 (0,0)（右键新建节点全落同一点的根因，验收反馈修）。**填充菜单时立即取值**：`Vector2 pos = contentViewContainer.WorldToLocal(evt.mousePosition)`（mousePosition 是面板坐标，须转内容坐标以容纳 pan/zoom），回调闭包只捕获 `pos` |
| 实验性 API 风险 | 作者稿纯 POCO 与画布解耦（§三），换画布数据不动 |

## 五、左栏资产树（PartCardTreeView，验收反馈重做版）

XH demo `SkillAssetTreeView` 模式：`TreeView` 双层树（Folder/ScriptableObject 图标、showBorder、useScrollView），条目显示「id 卡名」，卡按 id 排序、文件夹按名排序。

**交互全表**：单击卡=打开（窗口切卡前自动保存）；单击文件夹=仅选中；双击文件夹=展开/收起；**双击卡=重命名**；右键卡=重命名/删除（确认弹窗）；右键文件夹=新建卡/新建文件夹/重命名/删除（根禁删）；**空白处右键=在选中文件夹（无选中=根）新建**；**拖拽**=卡/文件夹拖入文件夹移动（`AssetDatabase.MoveAsset`），目标是自身或自身子孙 → `DragAndDropVisualMode.Rejected`；新建后自动展开父级+选中新项+（卡）打开并**直接弹重命名**；`projectChanged → Reload()` 同步 Project 窗口的移动/改名/删除。重命名弹窗 `RenamePopup`（XH 同款）：主窗居中、自动聚焦、回车确认/Esc 取消、非法文件字符清洗。

**踩坑记录（根因级）**：AssetDatabase/GUIDToAssetPath 一律**正斜杠**，Windows `Path.GetDirectoryName` 规范成**反斜杠**——两者直接 `==` 比较永不相等（验收反馈"卡片不可见"的根因）。本树统一封装 `NormalizeDir(path) = GetDirectoryName(path)?.Replace('\\','/')`，任何 dirname 比较前必须过它。

**建树数据源**：文件夹 `AssetDatabase.GetSubFolders` 递归；卡 `FindAssets("t:PartCardAuthoringAsset", new[]{folder})` 逐级过滤（NormalizeDir==folder 只列本级）。id 分配=全库现有最大 CardId+1（起点 100）。

## 六、主窗口（SkillEditorWindow）与编译器（PartCardCompiler）

**三栏装配**：工具栏 IMGUIContainer（保存/全览/导出卡池JSON/当前卡标识）+ 左 `PartCardTreeView.OnGUI(整块 ExpandHeight 区域)` + 中 `SkillGraphView`（flexGrow=1）+ 右参数面板 IMGUIContainer（宽 340）。`EditorApplication.update += PollTick`（选择同步）+ `projectChanged += 树 Reload`，`OnDisable` 成对退订并**自动保存**。

**右栏参数面板**：选中根（开卡自动选中）→ 卡级字段；选中节点 → 按 Kind 出字段（`Popup(label, value, values, names)` 值/名分离重载，枚举走 `Popup<T>` 泛型 Parse）；任何改动 `SetDirty` + 画布摘要刷新 + （Id 改动）左栏刷新；槽型改动根端口即时重建。

**编译映射三规则**（详细语义见 v2 §四，此处 as-built 要点）：

1. **目标切换=效果组边界**：链上 `NodeTargetScope≠ParentPassed` 或遇选择目标节点 → 断组开新组（Caster→Self、Chosen→Chosen、TargetSwitch→其 TargetMode）；组序=链序。
2. **并行分支（输出多连）=同层多组**：前缀断组后各分支独立递归，顺序=节点 X 坐标左→右。
3. **条件分支=ConditionalOp 递归**：Then/Else 子链编译为纯 op 数组。

**常驻双端口编译**：「触发」链=链首 TriggerConfigNode→`TriggerDef`（Timing 按 `.Preview` 后缀推导；ValueFilter 可选）——**链内单组单目标**（`TriggerDef.Effects` 是单个效果组，数据合同倒逼）：链内出现选择目标节点/节点目标切换→编译错误；「光环」链=属性修饰/赋予关键词节点序列→一个 `GameplayEffectDef{Permanent, Modifiers, GrantedTags}`，多链=多 def。入场/离场=各端口链→`Effects`（`OnSummonLate` 组带 `PlayAfterAnimation=true`）。

**导出管线**：全库逐卡 `Compile`（错误带节点定位汇总，任一错误/重复 id → **中止并列出**）→ `SkillJson.Serialize` → 写 `GameData/parts.json` → **`FusionCatalog.Load` 全量复验**（序列化器不跑巡检，加载入口才是完整校验通道）。**导入**：`SkillJson.Deserialize<PartCardConfig[]>` → 已有 id 跳过（作者稿是唯一事实源）→ `Decompile` 反编译建新卡：组目标≠Self→插入选择目标节点、逐 op 重建节点（条件递归挂 是/否 出口）、Trigger→触发配置节点+链、Auras→修饰/关键词链、自动布局（x 按端口列 380/560，y 每节点 +120）。

## 七、校验分层（什么时候报什么错）

| 时机 | 校验内容 | 反馈形式 |
|---|---|---|
| 连线创建 | 输入单进/禁环/双端口白名单/触发链首类型 | 连线当场拒绝 + Debug.LogWarning |

| 加载复验 | FusionCatalog 全量（标签/矩阵/引用） | 抛异常（不带病运行） |

## 八、定案记录（2026-10-28 决策者拍板）

1. **画布技术 = GraphView**。缓解实验性 API 风险：作者稿只存纯数据节点+坐标（自研 POCO），不存 GraphView 节点对象——换画布时作者稿与导出管线不动。
2. **常驻槽端口 = 「触发」+「光环」双端口**。触发链→TriggerDef、光环链→Aura（连线白名单只收属性修饰/赋予关键词），与《融合核心框架设计》§四 Triggers/Auras 并列结构一致；需求文档§6.2 已同步修订。附带编译约束（数据合同倒逼）：**触发链内单组单目标**——链内不许插选择目标节点/切节点目标。
3. **作者稿存储 = 每卡一个 .asset**（终态形态）：卡池=`Assets/Editor/SkillCards/Parts/` 文件夹，文件名=卡名，目录=左栏文件夹树；新建（自动 id=同类型最大+1）/重命名/删除确认/拖拽移动均已实现；Project 窗口操作经 `projectChanged` 等效同步。
4. **「获得行动点」op：M5 不做**。编辑器操作节点列表不含该项（M6 随行动点经济走缺口流程立项后再加）。
