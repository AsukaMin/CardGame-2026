# 单机卡牌游戏：技能系统设计

> 状态：v1（2026-10-18 立项轮定稿，代码随文档落地）。
> 定位：**gameplay-agnostic 的卡牌效果引擎**——只关心"实体、标签、效果、事件"四件事；回合、死亡、胜负、UI、手牌、行动点等战斗语义一概不知，全部由宿主（未来战斗核心）绑定。
> 参照物：`E:/Unity_Projects/XHFrameworkSkillDemo`（即时战斗 GAS demo）及其《技能系统设计解析》——借鉴映射见第二节。
> 代码位置：`Unity/Assets/Scripts/Battle/`（Unity 6000.3 / C# 9 / netstandard2.1）。
> 标注约定：【实现】=代码已如此；【约定】=使用方须遵守的契约；【预留】=接口已立、内容后补。

## 一、定位与铁律

| 维度 | 决策 |
|---|---|
| 程序集 | `Battle.asmdef`（零引用、`noEngineReferences: true`、namespace `Battle`）——技能系统是第一批文件，**未来战斗核心重写也进这个程序集** |
| 依赖方向 | `Fusion → Battle`（卡牌配置引用效果描述符）；Battle 不引用任何项目程序集（含 GameEvents） |
| 纯净性 | 纯 C# 零 UnityEngine、无 IO——一切数据构造注入 |
| 确定性 | 标签 Id=注册表声明序 int（**不用 string.GetHashCode**——跨运行不稳定）；聚合顺序、堆叠规则、触发顺序全部固定并测试固化；**不用反射读堆叠层数**（demo 已知缺陷不继承） |
| 结算模型 | 同步虚拟机：效果链=同步方法调用；事件 FIFO 队列排空 + 整链深度防护 64；耗时行为（Buff 到期、周期）由宿主在回合时点调引擎回头触发 |
| 数据驱动 | Data 层纯 POCO（无参构造、公开字段，Newtonsoft 友好）；新卡=新数据 |

**三层分离**（照搬 demo 的工程决策）：

| 层 | 内容 | 依赖 |
|---|---|---|
| Data（`SkillDefs.cs`/`SkillEffectDefs.cs`） | 全部描述符 POCO：操作/条件/目标/数值/触发器/持续效果/Cue | 无 |
| Runtime（其余文件） | 纯 C# 执行：标签/属性/实体/Spec/引擎 | Data |
| Editor（未来技能编辑器） | 只读写 Data 层 | Data |

**Data 层是未来技能编辑器的合同**：编辑器产出=Data 层 POCO，运行时零改动。本轮数据形状=节点数组+分支嵌套（图的无环特例）；demo 的 `SkillGraphData.nodes` 也是节点数组，未来升级连接表（端口遍历）不冲突。

## 二、与 GAS / XH demo 的对照（借鉴什么、改造什么、不搬什么）

| demo 子系统 | demo 设计 | 本系统取舍 |
|---|---|---|
| 三层分离 | Data 无逻辑 / Runtime 无编辑器依赖 | **全盘照搬** |
| ASC 形态 | 实体聚合属性/标签/技能/效果四容器 + 实体侧事件 | **拿**：`SkillEntity`（属性/标签/效果三容器+被授予的触发器）；弃 GameObject 绑定与 GASHost 单例（引擎实例持有全局注册表，构造注入纪律） |
| 标签系统 | 层级+祖先哈希父匹配；**引用计数**（多来源同标签，最后一个来源移除才真正摘除）；Set/Container 分工；HasTagExact | **拿全部语义**，实现换确定性 Id（见第三节） |
| 属性系统 | Attribute 双值（Base=Instant 永久改 / Current=聚合）+内嵌 Aggregator（脏标记重算）+clamp 钩子；聚合 `Override ?? (Base+ΣAdd) × ΠMultiply`；枚举分段字典容器 | **拿**（见第四节）；AggregatorMode（Paragon 减速规则）与 Meta 属性【预留】不实装 |
| 修饰器 | 四则 Add/Multiply/Divide/Override；数值来源 Fixed/Formula/MMC(属性捕获×系数, 快照/实时)/SetByCaller | **拿三档**：Const / SetByCaller / SourceAttribute(属性×系数)；Formula 表达式不搬（回合制卡牌数值简单；demo 自身两处公式能力分裂是已知缺陷）；快照语义【预留】字段（默认实时） |
| 效果系统 | Effect 一等公民：Instant 直改 Base；Duration 挂容器+授予标签+挂 Modifier（**以效果实例为 source 精准撤销**）；周期；堆叠（归属/上限/时长刷新/过期掉层）；标签五件套（asset/granted/applicationRequired/immunity/removeWith）+ongoingRequired | **核心采纳**（见第六节）：`GameplayEffectDef` 统一 Buff/毒/光环。溢出、周期重置等冷门堆叠策略【预留】枚举位 |
| 堆叠参与聚合 | Add×层数；Multiply 线性叠乘 `1+(m-1)×层数`；叠层只标脏不增删 Modifier | **拿聚合公式**；层数经修饰条目字段直读，不反射 |
| 执行上下文 | Caster/MainTarget/Targets/ParentInputTarget 四级目标；CustomData=SetByCaller 载体；克隆换目标（for-each） | **拿简化版**：`SkillContext{Source, MainTarget, CurrentTarget, Event, SetByCaller, LastResult}`——逐目标执行时切换 CurrentTarget，等价于克隆 |
| 被动/触发 | 事件端口：ASC 广播 GameplayEventType → 激活中的技能沿端口执行子图；属性变化桥接事件（Health 降→OnTakeDamage） | **拿思想换载体**：事件用**层级标签**而非枚举端口（加事件=加标签+发送点，技能侧零改动）；属性桥接不搬（属性 delta 推不出"谁打的"，管线事件自带来源） |
| 图驱动执行 | nodes+connections，SpecExecutor 沿端口深度遍历 | 本轮不引入连接表（见第一节"图的无环特例"）；端口思想以"生命周期钩子位"存在（持续效果的应用/周期/到期） |
| pending 缓冲 | 所有容器统一 `_isUpdating+pending列表` 防遍历中增删 | **拿**：效果容器、触发注册表、事件队列统一此模式 |
| GameplayCue | 独立表现体系+生命周期归属链 | 只留 `CueDef` 数据位；播放归宿主/表现层 |
| Cost/Cooldown 即 GE | Cost GE 是空类纯靠 modifier；CD=会过期的标签；充能 CD | 不实装（战斗经济，宿主域）；映射记录：效果卡充能档位≈Cost GE，无 CD 概念 |
| FormulaEvaluator / GASHost / 动画时间轴 / 投射物 / 放置物 / 位移 / Luban / 网络同步 | 即时制与基建 | 不搬（理由见第十一节） |

## 三、标签系统（`SkillTags.cs`）

GAS 的核心哲学：**标签是全框架的通用状态语言**——关键词、事件种类、效果身份、驱散匹配、触发订阅全走标签。

### 3.1 类型分工

| 类型 | 可变性 | 用途 |
|---|---|---|
| `SkillTag`（readonly struct） | 不可变 | 单个层级标签，如 `"Keyword.Taunt"`；int Id + 全名 + 祖先 Id 链 |
| `TagSet` | 不可变 | **配置期**静态集合（数据字段用 `string[]` 名称，加载时解析）；HasAny/HasAll/HasNone |
| `TagContainer`（实体持有） | 可变 + **引用计数** | **运行时**动态标签表；Add 计数 0→1 触发 `OnTagAdded`，Remove 计数 1→0 触发 `OnTagRemoved`，中间态只改计数 |

**层级匹配**：`"Event.Damage.Applied"` 拥有 `"Event.Damage"` 与 `"Event"`——`Has(父标签)==true`；`HasExact` 提供精确匹配。触发器订阅父标签即可捕获全部子事件。

**引用计数解决的正确性问题**：两个效果都给目标挂 `Keyword.Taunt`，一个到期时不能摘标签（另一个还在给）——只有最后一个来源移除时标签才真正消失。

### 3.2 注册表与确定性 Id

- `TagRegistry.Declare(name)`：声明即注册，自动注册全部祖先；同名幂等返回同一实例。
- `TagRegistry.Resolve(name)`：解析已声明标签；未知名=配置错误，抛异常（加载期暴露，不带病运行）。
- **Id 只做运行期内等值比较，跨运行不持久化**；配置侧（JSON/Data 字段）一律用字符串全名。声明序=Id 序，行为与 Id 数值无关，重放安全。

### 3.3 项目标签清单（`SkillTags` 静态类，声明即文档）

| 命名空间 | 标签 | 说明 |
|---|---|---|
| `Keyword.*` | Taunt / Poison / Lifesteal | 行为关键词载体（行为=宿主管线钩子或触发器数据，见第十节） |
| `Event.Damage.*` | Preview / Applied | 引擎自发：结算前（可改写）/ 结算后 |
| `Event.Heal.*` | Preview / Applied | 同上 |
| `Event.Effect.*` | Applied / Removed | 引擎自发：持续效果挂上/移除（含到期） |
| （宿主自声明） | 如 `Event.Turn.Started`、`Event.Unit.Died`、`Event.Card.Drawn` | 战斗语义标签——**宿主声明+喂养，引擎不知其含义** |

【约定】标签命名用点分层级、名词大写驼峰；事件标签一律 `Event.*` 前缀，事前时点用 `.Preview` 后缀。

## 四、属性系统（`SkillAttributes.cs`）

### 4.1 双值模型（GAS 铁律）

- **BaseValue**：永久值，只被 Instant 修改直写（伤害扣血、永久增益）。
- **CurrentValue**：`聚合(BaseValue, 活跃修饰)`，持续效果挂上/摘除/叠层只标脏重算，效果到期自动回落。

### 4.2 聚合公式（顺序固定）

```
CurrentValue = Override ?? (BaseValue + Σ Add×层数) × Π (1 + (Multiply-1)×层数)
```

先加后乘、Override 直接覆盖（慎用）；数值一律 double，容器出口处取整（AwayFromZero）。

### 4.3 修饰条目（`AttributeModifier`）

```
AttributeId Attribute;  ModOp Op (Add/Multiply/Override);  double Magnitude;
object Source;          // 挂靠来源（ActiveEffectSpec）——RemoveModifiersFromSource 精准撤销
int StackCount = 1;     // 由所属效果推进，聚合时参与计算（字段直读，不反射）
```

数值大小由 Data 层 `ScopedValue` 在挂靠时求值固化（持续效果的修饰在**应用时刻**求值，快照语义【预留】）。

### 4.4 容器与联动（`SkillAttributeContainer`）

- `AttributeId` 枚举分段预留：`Attack=1 / MaxHp=2 / CurrentHp=3`（1-99 战斗三件套，后续按需扩段）。
- **MaxHp↔CurrentHp 联动**【约定】：MaxHp Current 上升时 CurrentHp 同步抬升等量、下降时夹紧（卡牌惯例，沿用旧融合核心规则）。
- `CurrentHp` clamp 到 `[0, MaxHp.CurrentValue]`。
- `OnAttributeChanged(AttributeId, before, after)`：CurrentValue 实际变化后触发（供实体侧/宿主监听）。

## 五、Data 层契约（`SkillDefs.cs` + `SkillEffectDefs.cs`）

全 POCO；`null` 数组视为空；字段默认值即合理默认。

### 5.1 目标选择（`TargetMode`，相对效果来源的 TeamId）

`Chosen`（命令传入主目标）/ `Self`（来源实体；`Caster` 同义保留）/ `Instigator`、`EventTarget`（事件引发者/承受者，仅触发上下文有效，否则解析为空）/ `AllAlliedUnits`、`AllOpposingUnits`、`AllUnits` / `RandomOpposingUnit` / `AlliedLeader`、`OpposingLeader`（主战者=Leader 实体）。

### 5.2 数值定义（`ScopedValue`）

```
ValueSourceKind Kind = Const;    // Const / EventValue(事件携带值) / SetByCaller(上下文按键取值) / SourceAttribute(来源实体属性×系数)
double Value; string Key; AttributeId Attribute; double Coefficient = 1; bool UseSnapshot;  // 快照【预留】
```

怪兽卡引用自身身材=SourceAttribute；效果卡=Const；主战者（Leader）无攻击底数，引用 Attack 自然得 0——规则由数据形状自动成立。

### 5.3 Instant 操作族（`EffectOp` 基类）

| 操作 | 字段 | 语义 |
|---|---|---|
| `DamageOp` | Amount:ScopedValue, Kind | 经结算管线（见 7.1）扣 CurrentHp 的 Base 值 |
| `HealOp` | Amount:ScopedValue | 经结算管线回复，上限夹紧 |
| `ModifyAttributeOp` | Attribute, Op, Magnitude:ScopedValue, Duration, Rounds | Duration=Permanent→直改 Base（永久）；否则→引擎包装为隐式持续效果携带该修饰（到期回落） |
| `GrantTagOp` | Tag, Duration, Rounds | 统一经持续效果载体（grantedTags），可驱散 |
| `RemoveTagOp` | Tag | **按标签驱散**：移除目标身上 grantedTags 命中的持续效果（引用计数保护，不直接摘标签） |
| `ApplyEffectOp` | Effect:GameplayEffectDef | 施加持续效果（Buff/毒/光环的唯一入口） |
| `ConditionalOp` | Condition, ConditionTarget, Then[], Else[] | 条件分支，可嵌套 |
| `ModifyEventMagnitudeOp` | Delta, Scale=1 | **仅 Preview 上下文合法**：改写待结算数值（减伤/易伤/免疫=归零）；其余上下文=配置错误抛异常 |

### 5.4 持续效果（`GameplayEffectDef`）——Buff/毒/光环的统一载体

```
string Name;                          // 调试用
string[] AssetTags;                   // 身份标签：驱散匹配 + 堆叠归属
string[] GrantedTags;                 // 挂上时授予目标（引用计数），移除时摘除
string[] ApplicationRequiredTags;     // 目标必备（缺则不施加）
string[] ApplicationImmunityTags;     // 目标带则免疫
EffectDurationKind Duration = Rounds; // Instant / ThisPhase / Rounds(N) / Permanent
int Rounds = 1;
bool PeriodicEachRound;               // 每回合周期执行（宿主回合时点驱动）
EffectGroupDef PeriodicEffects;       // 周期效果组：执行上下文 Source=效果宿主（Self 即宿主——"毒对自己跳伤"的写法）
AttributeModifierDef[] Modifiers;     // 属性修饰（Attribute/Op/Magnitude:ScopedValue）
StackAggregation StackBy = ByTarget;  // BySource（同源叠层）/ ByTarget（同类叠层）
int StackLimit;                       // 0=无限
bool StackRefreshDuration = true;     // 叠层刷新剩余回合
bool ExpirePerStack;                  // 到期：true=掉一层并刷新，false=整效果移除
```

**堆叠语义**：可堆叠判定=同一 `GameplayEffectDef` 引用（配置身份）+ StackBy 决定是否再比 Source 实体。叠层后属性立即吃到层数（聚合公式参与），不增删修饰条目。

**光环 = 挂在别人身上的持续效果**：宿主在实体离场时调 `RemoveEffectsFromSource(实体)` 精准撤销——不再需要"静态桶全量重算"。

### 5.5 触发器（`TriggerDef`）

```
string EventTag;                // 层级标签名；父标签命中全部子事件
TriggerTiming Timing = After;   // After（事后响应）/ Preview（事前改写——仅 *.Preview 标签合法）
bool SelfOnly;                  // 仅当事件承受者=宿主单位时触发——"我受伤时反弹"类个人被动的必备开关
                                //（否则宿主会响应场上一切同类事件；世界级触发器忽略此位）
ConditionDef Filter;            // 可选：对事件承受者求属性/标签条件
EventValueCondition ValueFilter;// 可选：对事件数值求值（"受到 ≥3 伤害时"）
EffectGroupDef Effects;         // 触发执行的效果组
bool Once;                      // 每场一次
```

### 5.6 条件族（`ConditionDef` 基类）

| 条件 | 字段 | 求值对象 |
|---|---|---|
| `AttributeCompareCondition` | Attribute(AttributeId), Op(六种), ValueType(Fixed/PercentOfMaxHp), Value | 由 `ConditionalOp.ConditionTarget` 决定：Current（被作用目标）/ Source（施法者）/ MainTarget（命令主目标） |
| `EventValueCondition` | Op, Value | 事件 Magnitude（触发器 ValueFilter / 条件上下文有事件时） |
| `HasTagCondition` | Tag, Exact=false | 同上求值对象 |

### 5.7 效果组（`EffectGroupDef`）

```
TargetMode Target = Chosen;  EffectOp[] Ops;  CueDef[] Cues;  bool PlayAfterAnimation;
```

`CueDef{ string Cue; double Param; }`——表现指令数据位（宿主/表现层解释播放，引擎不演）；`PlayAfterAnimation` 数据位（演出时序端口【预留】归宿主与表现层协商）。

## 六、运行时：实体与持续效果

### 6.1 `SkillEntity`（ASC 形态）

```
int Id;  int TeamId;  EntityKind Kind (Unit/Leader);  string Name;
SkillAttributeContainer Attributes;   // 属性三容器之一
TagContainer Tags;                    // 引用计数标签
ActiveEffectContainer Effects;        // 在身的持续效果（pending 缓冲防遍历中增删）
```

实体侧事件经容器（`OnAttributeChanged` / `OnTagAdded/Removed`）暴露；引擎不再另设实体级事件。

### 6.2 `ActiveEffectSpec`（持续效果运行时实例）

- 状态：Def/Target/Source/StackCount/RemainingRounds/已挂修饰列表/已授予标签。
- `Apply()`：校验 Required/Immunity → 挂修饰（Source=自身，精准撤销）→ 授予 GrantedTags（引用计数）→ 发 `Event.Effect.Applied`。
- `AddStack()`：层数+1（上限拒绝），按策略刷新剩余回合，标脏重算。
- `TickRound()`（引擎时点调用）：周期执行 PeriodicEffects → 剩余回合递减 → 到期按 ExpirePerStack 掉层或 `Remove()`。
- `Remove()`：摘修饰（按 Source 精准撤销）→ 摘 GrantedTags → 发 `Event.Effect.Removed`。

### 6.3 `SkillContext`（执行上下文）

```
SkillEntity Source;         // 效果来源（效果卡=施法 Leader；部位卡=宿主单位；触发器=触发器宿主）
SkillEntity MainTarget;     // 命令传入的主目标（可空）
SkillEntity CurrentTarget;  // 当前被作用实体（逐目标切换，for-each 等价物）
GameplayEvent Event;        // 触发上下文的事件（可空）
Dictionary<string,double> SetByCaller;   // 宿主/上游传值（ScopedValue 取数）
object LastResult;          // 最近结算结果（如 DamageResult——数值/是否致死），供触发器与 Cue 引用
```

## 七、运行时：引擎与结算管线（`SkillEngine.cs`）

门面实例（宿主持有，随宿主生灭），构造注入 `ISkillWorld`。

### 7.1 伤害/治疗管线（三段）

```
Prepare：构造可改写载荷（DamageContext{Target, Source, Amount, Kind}）
        → 同步派发 Preview 事件（Event.Damage.Preview）
        → Preview 触发器经 ModifyEventMagnitudeOp 改写 Amount（Delta/Scale/归零）
        → 下限夹紧 0
Apply：直写 CurrentHp 的 Base 值（容器联动/夹紧/发属性变化事件）
Notify：入队 Event.Damage.Applied（Magnitude=实际变化量）→ 队列排空
```

`ResolveDamage/ResolveHeal(source, target, scopedValue或double, kind) → DamageResult/HealResult`。Preview 同步执行（必须赶在落地前完成）；Preview 触发器内再造成伤害=嵌套走完整管线，受深度防护。

### 7.2 事件队列与触发

- `GameplayEvent { SkillTag Tag; SkillEntity Instigator; SkillEntity Target; double Magnitude; DamageSourceKind Kind; }`——通用载荷，事件种类即标签。
- 事后事件一律入 FIFO 队列；宿主命令结束后（或每次入队后）排空。**深度防护 64**：触发链（反伤→死亡→亡语→再反伤）超限即断，防数据造环。
- 触发顺序=**注册顺序**（宿主控注册序=召唤序→槽位序→声明序，确定性由宿主掌握）；事件分发给注册表**快照**，处理期间新注册者下一事件生效。
- `Raise(GameplayEvent)`：宿主喂战斗语义事件（回合开始/单位死亡/抽牌……引擎不知其含义）的唯一入口；引擎自发事件走同一队列。

### 7.3 时点推进（宿主回合时点调用）

| 方法 | 宿主调用时机 | 语义 |
|---|---|---|
| `ExpirePhase()` | 宿主定义的相位结束（战斗=回合结束） | 清除全部 ThisPhase 效果 |
| `TickRound()` | 宿主定义的轮次开始（战斗=回合开始） | 逐效果：周期执行→Rounds 递减→到期（掉层或移除） |

时长词汇（ThisPhase/Rounds）**语义由宿主绑定**——引擎只记账。

### 7.4 撤除与清理

| 方法 | 用途 |
|---|---|
| `RemoveEffectsFromSource(entity)` | 撤销该实体施加的全部效果（**光环撤除**：宿主在单位离场时调用） |
| `UnregisterTriggers(entity)` | 注销该实体名下全部触发器（离场） |

### 7.5 主动执行入口

`Execute(EffectGroupDef[], SkillContext)`：逐组解析目标（经 ISkillWorld）→ 逐目标切换 CurrentTarget → 逐 op 经工厂分发 Spec 执行。宿主用它在"效果卡打出/入场槽触发/意图施法"等时机执行效果组。

### 7.6 扩展点

`RegisterOp<TOp>(factory)`：宿主注册玩法 op（抽牌/得点等）——工厂实例级注册，自带 op 走内置工厂。

## 八、事件层：为什么不复用 GameEventBus

引擎内部事件层与 `GameEventBus`（Scripts/GameEvents，全局静态总线）**共存不迁移**，不复用的理由：

1. **生命周期**：总线全局静态跨场存活；触发器是宿主结算规则的实例状态，必须随引擎实例（随一场战斗）生灭——挂全局总线就是跨场残留隐患。
2. **派发语义**：总线立即同步派发且**重入硬禁**（回调内 Send 抛异常）；触发链式反应（反伤→死亡→亡语→伤害）是技能系统的常态，需要 FIFO 队列+深度防护，语义冲突。
3. **载荷形态**：总线一事件一 struct 类型（类型即键）；触发器要通用载荷+**标签匹配**（父标签捕获子事件、数据侧用字符串名订阅）——这是"事件与技能解耦"的机制核心。
4. **确定性**：总线派发顺序=外部订阅序；触发顺序是玩法规则（注册序），必须由引擎掌握并测试固化。
5. **事前可改写**：Preview 时点要求接收方能改写待结算数值（DamageContext），总线的 `in T` 只读投递表达不了。

## 九、宿主接入指南（未来战斗核心怎么用）

```
1. 实现 ISkillWorld（EntitiesOfTeam/NotOfTeam/LeaderOfTeam/Find/Random——阵营=TeamId，随机源=宿主种子）
2. new SkillEngine(world)；实体 = new SkillEntity{ TeamId, Kind, ... }（属性 SetBase 初始化）
3. 召唤：注册部位卡 Triggers（engine.RegisterTrigger(单位, def)）+ 施加 Auras（ApplyEffectOp 载体）
4. 玩家命令：PlayCard → engine.Execute(档位效果组, ctx{Source=Leader, MainTarget=玩家选的目标, SetByCaller=…})
5. 攻击结算：engine.ResolveDamage(攻方, 守方, 攻方Attack, Combat)（互殴=两次 Resolve，死亡观察由宿主）
6. 战斗语义事件：在回合开始/单位死亡/抽牌等时点 engine.Raise(new GameplayEvent{Tag=Event.Turn.Started...})
7. 回合时点：回合结束 engine.ExpirePhase()；回合开始 engine.TickRound()
8. 单位离场：engine.RemoveEffectsFromSource(单位) + engine.UnregisterTriggers(单位)
9. 玩法 op：engine.RegisterOp<DrawCardsOp>(...) 注册抽牌/得点
10. 行为关键词：剧毒/吸血等=宿主在管线 Preview 阶段注册的钩子或触发器数据（规则定义待战斗核心轮）
```
