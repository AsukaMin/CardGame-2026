# 单机卡牌游戏：目录结构与资源加载

> 接续《单机卡牌对战游戏-板块划分与离线补丁方案》《单机卡牌游戏-简化版UI框架设计》。约定：Unity 工程文件夹叫 `CardGame`，解包的美术素材库叫 `CardGame_Arts`。本文定目录结构、各文件夹职责、各类资源在代码里的加载调用点。

## 一、完整目录树

```
CardGameProject/                      ← 仓库根（名字随意，下面是"工程外围"五个目录）
├── Excel/                            ← 源表，唯一人工编辑点
│   ├── cards.xlsx
│   └── levels.xlsx
├── Tools/                            ← 导表 + 打补丁脚本（推荐做成 Unity Editor 菜单）
├── CardGame_Arts/                             ← 素材库（解包的美术资源，原料仓库，只增不改）
├── GameData/                         ← 运行时 JSON 母本（各工具按文件分工刷新，不进 Unity Assets）
│   ├── manifest.json
│   ├── effect_cards.json             ← 技能编辑器导出（效果卡）
│   ├── part_cards.json               ← 技能编辑器导出（部位卡）
│   ├── monster_sleeves.json          ← （未来）Excel 导表产出（卡套纯数值表）
│   ├── levels.json                   ← （未来）Excel 导表产出（关卡）
│   └── art/                          ← 热更散图（从 CardGame_Arts 挑进来的、按文件名加载的）
│       └── 卡001_炎爆术.png
├── PatchSource/                      ← 快递箱（打包按钮生成，可随时删）
├── Build/                            ← 整合包输出
│   └── CardGame_v1.0/
│       ├── CardGame.exe              ← Unity 打包产物
│       ├── Config/                   ← 出包时从 GameData/ 整体复制
│       └── Mods/                     ← 空着，给朋友放补丁
└── CardGame/                         ← Unity 工程本体
    ├── Assets/
    │   ├── Scripts/
    │   │   ├── Battle/               ← 纯 C# 战斗核心（不引用 UnityEngine）
    │   │   ├── Meta/                 ← 局外：卡组编辑、存档、货币
    │   │   ├── UI/                   ← UIWindow/UIManager/UIParam + 各窗口类
    │   │   ├── ConfigGen/            ← 导表生成的 C# 类（只读，partial 扩展另放）
    │   │   └── Loader/               ← 启动：ConfigDatabase / ArtStore / manifest 校验
    │   ├── Art/                      ← UI 底子图（九宫格、按钮框、字体），从 CardGame_Arts 挑进来的
    │   ├── CardAuthoring/            ← 技能编辑器 SO 源（编辑期物料：非 Resources、不进包、不热更）
    │   │   ├── EffectCards/          ←   效果卡编辑源（Tools/技能编辑器）
    │   │   └── PartCards/            ←   部位卡编辑源
    │   └── Resources/
    │       └── UI/                   ← 窗口预制体（约定：UI/窗口名=类名）
    └── Packages/ ProjectSettings/    （Unity 自带，不动）
```

### 三个关键设计理由

1. **Excel、CardGame_Arts、GameData、PatchSource 全在 Unity 工程外面。** `Assets/` 里的东西会被 Unity 当资源导入——几千张素材、xlsx、中间产物 JSON 塞进去是导入时间和库体积的灾难。它们是"原料和产物"，不是游戏资源；Unity 里只进最终打标的：代码、UI 预制体、UI 底图，外加**编辑源数据** `Assets/CardAuthoring/`（技能编辑器的 SO——必须留在 Assets 内才能被编辑，但放在 Resources 之外：Resources 里的东西会进玩家包体，编辑源随包发布纯属浪费，且违反下文"Resources 只放 UI 预制体"）。
2. **CardGame_Arts 的分流规则**——一张图从 CardGame_Arts 出来去两个地方之一：
   - `CardGame/Assets/Art/`：永远不会通过补丁换的（按钮底、卡框、字体等 UI 框架件）
   - `GameData/art/`：会换内容、走文件名加载的热更图（卡面、头像、关卡插图）
3. **ConfigGen 单独成目录**，和手写代码物理隔开，"看见目录就知道别动"。

### 数据流总览

```
CardGame_Arts ──人工挑──> CardGame/Assets/Art（打包图）
 │            └> GameData/art（热更图）
Excel ──导表──> CardGame/Assets/Scripts/ConfigGen（生成类，写代码用）
 │          └> GameData/*.json（数据母本：卡套/关卡等纯数值表）
Assets/CardAuthoring SO ──技能编辑器导出──> GameData/effect_cards.json + part_cards.json
GameData ──出整合包──> Build/CardGame_v1.0/Config/
GameData ──打包按钮──> PatchSource ──zip──> 朋友的 Game/Mods/
```

### git 建议

- `CardGame/Library/`、`PatchSource/`、`Build/` 进 .gitignore（可再生产物）
- `CardGame_Arts/` 若是几 GB 素材堆，考虑网盘另存不进 git——仓库存"成品"不存"原料堆"

## 二、GameData ↔ 运行时 Config 的对应

`GameData/` 是**开发侧母本**，运行时对应物是 **exe 旁边的 `Config/`**，出包时整份复制、内容一模一样：

```
开发时（你的电脑）                 运行时（朋友电脑）
CardGameProject/                  Build/CardGame_v1.0/
└── GameData/          ──出包复制──>  ├── CardGame.exe
    ├── cards.json                    └── Config/   ← 就是它
    ├── levels.json
    └── art/
```

要点：

1. **不在 Unity 工程里**——JSON 不走 Unity 资源导入，游戏启动用文件 IO 直接读外部目录（补丁能生效的前提）。
2. **补丁永远不碰原件**：改表改 `GameData/`，补丁落朋友机器 `Mods/`，`Config/` 从安装那天起没被写过，直到下个整合包整体替换。
3. 运行时查找顺序：`Game/Mods/ → Game/Config/ → 代码默认值`。

### 与现项目（TruckUpSimulatorOnline）的映射

| 卡牌项目 | 现项目实际 | 角色 |
|---|---|---|
| `Excel/` | `Excel/`（仓库根） | 源表，同名同角色 |
| `GameData/` | `Unity/Assets/Res/Config/`（1000+ 个 config_*.txt） | 客户端运行时配置数据 |
| （没有） | 根目录 `Config/` | 服务器配置——卡牌项目没服务器，没这个 |
| `Mods/` | （无对应） | 网游走下载管线，不需要本地覆盖层 |

**位置差异的原因**：现项目配置放 `Assets/Res/Config/` 里面，因为靠 AB 打包 + 服务器下载热更（网游做法）；卡牌项目放 Assets 外面，因为靠"文件 IO 读外部目录 + 人肉放补丁"。

## 三、各类资源的加载调用点

总表（`实际位置` 列的 `→` 读作"找不到就退而求其次"，即查找优先级）：

| 资源类别 | 实际位置 | 加载时机 | 代码里的调用点 |
|---|---|---|---|
| 配置表 JSON | Mods/ → Config/ | 启动一次性 | `Loader/ConfigDatabase` |
| 热更散图（卡面等） | Mods/art/ → Config/art/ | 首次用到懒加载 | `Loader/ArtStore` |
| UI 窗口预制体 | 包内 Resources/UI/ | 窗口首开 | `UI/UIManager` |
| UI 底图 | 包内 Assets/Art/ | 无代码加载 | Inspector [SerializeField] |
| 生成 C# 类 | 编译进包 | 不是加载，直接调 | 任何业务代码 |
| 存档 | **Application.persistentDataPath** | 进主界面/保存时 | `Meta/SaveSystem` |

### 1. 配置表 JSON —— 启动一次读完

```csharp
// Loader/ConfigDatabase.cs —— 全项目唯一知道配置路径的类
public static class ConfigDatabase
{
    public static CardTable Cards { get; private set; }
    public static LevelTable Levels { get; private set; }
    public static string BaseVersion { get; private set; }
    public static string PatchVersion { get; private set; }

    public static void LoadAll(string gameRoot)
    {
        string configDir = Path.Combine(gameRoot, "Config");
        string modsDir   = Path.Combine(gameRoot, "Mods");

        var baseManifest = ReadManifest(configDir);
        var patchManifest = File.Exists(Path.Combine(modsDir, "manifest.json"))
            ? ReadManifest(modsDir) : null;
        if (patchManifest != null && patchManifest.MinAppVersion > baseManifest.Version)
            throw new PatchNeedNewBaseException();   // UI 层接住弹"请装新整合包"

        Cards  = new CardTable(LoadJson(modsDir, configDir, "cards.json"));
        Levels = new LevelTable(LoadJson(modsDir, configDir, "levels.json"));
        BaseVersion = baseManifest.Version;
        PatchVersion = patchManifest?.Version ?? "无";
    }

    static string LoadJson(string modsDir, string configDir, string fileName)
    {
        string p = Path.Combine(modsDir, fileName);          // ① 先查 Mods/
        if (File.Exists(p)) return File.ReadAllText(p);      //    有 → 用补丁版
        return File.ReadAllText(Path.Combine(configDir, fileName)); // ② 退回 Config/
    }
}
```

业务代码只认 `ConfigDatabase.Cards.Get(id)`，路径知识锁死在这一个类里。主流程第一步调 `LoadAll`，没加载完不进主菜单。

### 2. 热更散图 —— 懒加载 + 缓存池

```csharp
// Loader/ArtStore.cs
public static class ArtStore
{
    static readonly Dictionary<string, Sprite> cache = new Dictionary<string, Sprite>();
    static string[] searchDirs;   // 启动时填：{ gameRoot/Mods/art, gameRoot/Config/art }

    public static Sprite Get(string artName)   // 例：Get("卡001_炎爆术")
    {
        if (cache.TryGetValue(artName, out Sprite s)) return s;
        foreach (string dir in searchDirs)
        {
            string file = Path.Combine(dir, artName + ".png");
            if (!File.Exists(file)) continue;
            Texture2D tex = new Texture2D(2, 2);
            tex.LoadImage(File.ReadAllBytes(file));
            s = Sprite.Create(tex, new Rect(0, 0, tex.width, tex.height), new Vector2(0.5f, 0.5f));
            cache[artName] = s;
            return s;
        }
        return null;   // 调用方显示占位灰图
    }
}

// UI/CardView.cs —— 调用位置就是刷卡牌的 UI 组件
public void Bind(CardData card) => artImage.sprite = ArtStore.Get(card.ArtName);
```

Mods 优先的实现 = **搜索目录有序**，不是每张图查两次表。

### 3. UI 窗口预制体 —— 只在 UIManager 里

`Resources.Load<GameObject>("UI/" + winName)` 全项目仅此一处；其他代码开窗一律 `UIManager.I.Show("DeckWindow", p)`。

### 4. UI 底图 —— 零代码

九宫格、按钮框等不热更的图，预制体 Inspector 直接引用 `Assets/Art/` 的 Sprite。这就是"会不会走补丁"分流的全部意义：**会换的才配拥有加载器**。

### 5. 生成的 C# 类 —— 编译期直接调

`ConfigGen/Card.Generated.cs` 不经过加载，随包编译，提供的是访问 API：

```csharp
CardConfig c = ConfigDatabase.Cards.Get(1001);   // JSON 是数据（ConfigDatabase 装），生成类是容器和访问器（ConfigGen 定义）
```

生成类自带"把 JSON 反序列化成自己"的构造逻辑，供 ConfigDatabase 调。

### 6. 存档 —— 唯一用 persistentDataPath 的地方

存档不放 exe 旁边——Config/Mods 语义是"官方数据+补丁"，且 Program Files/Steam 库可能没写权限：

```csharp
// Meta/SaveSystem.cs
static string SaveDir => Path.Combine(Application.persistentDataPath, "saves");
// Windows 实际：C:\Users\<用户>\AppData\LocalLow\<公司名>\<产品名>\saves\

public void SaveDeck(Deck deck)
    => File.WriteAllText(Path.Combine(SaveDir, deck.Name + ".json"),
                         JsonConvert.SerializeObject(deck));

public Deck LoadDeck(string name)
{
    string p = Path.Combine(SaveDir, name + ".json");
    return File.Exists(p) ? JsonConvert.DeserializeObject<Deck>(File.ReadAllText(p)) : null;
}
```

存档不参与 Mods 覆盖，玩家进度永远以 persistentDataPath 为准。

## 四、路径纪律

- 全项目文件路径只允许出现在**四个类**里：`ConfigDatabase`（配置表）、`ArtStore`（热更图）、`UIManager`（窗口预制体）、`SaveSystem`（存档）。业务代码里出现 `Path.Combine` 就是坏味道——要么归这四类，要么给新资源类型建第五个 Loader。
- **战斗核心连这四个类都不碰**：`Battle` 构造函数接收已加载好的数据（如 `ConfigDatabase.Cards`），此后纯内存运算——这是它能脱离 Unity 单独测试的原因。
- 编辑期第五个路径持有者：`CardPoolExporter`（技能编辑器导出器，Editor 程序集里唯一知道 GameData 路径的类）——运行时四持有者不变，编辑器侧其余代码（窗口/画布/编译器）零路径知识。
- 人工编辑点分工：**纯数值表以 Excel 为唯一人工编辑点**（卡套/关卡等）；效果卡/部位卡的结构化数据以技能编辑器（`Tools/技能编辑器`）为唯一人工编辑点。两侧以**卡牌 id** 关联：表格管名称/描述/卡面，编辑器管效果结构与部位卡数值；未来 Loader 按 id join，join 不到效果数据的表格行报缺失（删卡须两边同步删）。
