> 标注约定：【实现】=代码已如此；【约定】=使用方须遵守的契约；【预留】=接口已立、内容后补。

## 一、设计目标与边界

| 维度 | 决策 |
|---|---|
| 纯净性 | 纯 C#，**零 UnityEngine 引用**——由 `Battle.asmdef`（`noEngineReferences: true`、零 references）编译期强制，不是口头纪律 |
| 无 IO | 不碰文件、不碰路径（"业务代码里出现 Path.Combine 就是坏味道"）；一切数据经 `BattleSetup` **构造注入** |
| 对 UI 通道 | 只有两条：事件广播（报事实）+ 命令方法（返回结果对象）；外加一个只读快照做全量刷 |
| 可测试性 | 可脱离 Unity 单独编译运行：dotnet harness 冒烟 + EditMode 测试双通道 |
| 数据驱动 | 效果=POCO 描述符 + 解释器执行；**新卡=新数据，零代码改动**（补丁方案文档的硬要求） |
| 确定性 | 一切随机走种子化 `Rng`；同种子+同操作序列=同终局（复现 bug 的锚点） |

**程序集与命名**：每个程序集一个扁平 namespace，不做子层级——战斗核心全部 `namespace Battle`（与 FSM 的做法一致）。承重墙是 asmdef，namespace 只是门牌。门面类定名 `BattleSession`（避开 `Battle.Battle`）。测试程序集 `Battle.Tests`（仅 Editor）通过 `InternalsVisibleTo` 做白盒验证。

## 三、对外契约（使用方只看这一节）

### 3.1 核心 → UI：`BattleEvents` 事实广播

事件只报**既成事实**（过去时态），核心用 `?.Invoke` 发射、不知道谁在听——无 UI 也能完整跑（冒烟已验证）。UI 侧纪律照抄 UI 框架文档：**OnShow 订阅、OnHide 退订，订阅后立即 `GetSnapshot()` 全量刷**。

| 事件 | 签名 | 触发时机 |
|---|---|---|
| `OnHpChanged` | `(int id, int newHp)` | 任何伤害/治疗后；id=单位实例 Id 或主战者 Id |
| `OnCardDrawn` | `(int cardInstanceId)` | 抽牌进手 |
| `OnCardPlayed` | `(int cardInstanceId)` | 效果卡打出（结算前） |
| `OnCardDiscarded` | `(int cardInstanceId)` | 主动弃牌 |
| `OnUnitSummoned` | `(int unitId)` | 单位上场（入场槽触发前） |
| `OnUnitDied` | `(int unitId)` | 死亡结算完毕（已进墓地、离场槽已触发） |
| `OnTurnStart` | `(int turnNumber)` | 每个玩家回合开始（含开局第 1 回合） |
| `OnActionPointsChanged` | `(int newPoints)` | 点数任何变动 |
| `OnIntentRevealed` | `(IReadOnlyList<Intent>)` | 新意图揭示（开局 + 每次敌方回合结束） |
| `OnBattleEnd` | `(BattleResult)` | 终局，恰好一次 |

### 3.2 UI → 核心：命令方法（要返回值、要失败原因）

| 命令 | 校验顺序（失败即返回、无副作用） |
|---|---|
| `PlayCard(handIndex, tierIndex, chosenTargetId = 0)` | 阶段 → 手牌存在 → 档位存在 → 目标合法 → **扣费** → 结算 |
| `SummonMonster(rosterIndex, chosenTargetId = 0)` | 阶段 → 名单状态 Available → 场面上限 → **扣费** → 上场；chosenTargetId 透传给入场效果链（"入场时选目标"类怪兽卡的通道，见第五节表现挂起） |
| `Attack(attackerUnitId, targetId)` | 阶段 → 我方单位 → 本回合未攻击 → 目标合法 → 嘲讽 → 结算 |
| `Discard(handIndex)` | 阶段 → 手牌存在 → 移除 → 回复钩子 |
| `EndTurn()` | 阶段 → 玩家回合结束 → 整个敌方回合 → 下个玩家回合 |

返回 `PlayResult { Success, Reason, Error }`。`FailReason` 全集：`NotPlayerMain / BattleFinished / CardNotFound / TierNotFound / NotEnoughPoints / RequiresUnitTarget / InvalidTarget / UnitNotFound / NotFriendlyUnit / AlreadyAttacked / TauntViolation / SleeveNotAvailable / FieldCapReached`。

**保证**：失败命令零副作用（扣费总在校验之后）；终局后任何命令返回 `BattleFinished`，状态冻结。

### 3.3 快照与终局

- `GetSnapshot()` → `BattleSnapshot`：双方主战者血量、场上单位（有效攻血/嘲讽/已攻击）、手牌（各档位费用与标签）、名单（召唤费/状态）、牌库/墓地计数、意图描述文本。**订阅事件后先刷它，之后靠事件增量更新**。
- `Result`（或 `OnBattleEnd` 事件载荷）→ `BattleResult`：胜负、回合数、`RemainingActionPoints`（run 内带到下一场）、`RecoverablePartCardIds` / `DestroyedPartCardIds`（战后部位卡回收清单）、`SurvivorUnitIds`。**run 层从这里接管，战斗核心不关心局外。**

### 3.4 Id 约定【约定】

| 对象 | Id 规则 |
|---|---|
| 玩家主战者 | 常量 `BattleSession.PlayerHeroId = 1` |
| 敌方主战者 | 常量 `BattleSession.EnemyHeroId = 2` |
| 场上单位 | 自 100 递增 |
| 卡牌实例 | 自 1000 递增 |
| 配置 Id | 导表来源，实例 Id 与其无关联 |

## 四、回合循环（显式状态机）

`BattlePhase`：`NotStarted → PlayerMain ⇄ EnemyTurn → Finished`。线性回合循环，**不复用 StateTree**——其层级/并行能力在此用不上（StateTree 留给表现层驱动）。

**开局时序**（构造函数即开局，事件顺序是 UI 首帧刷新的契约）：

```
注入校验（名单/敌方池 Validate：≥1 身材槽部位卡，缺失即抛异常——整备阶段保证、核心只防御）
→ 初始化双方主战者血量 → 组牌库（FixedDeckOrder 或种子洗牌）
→ 抽起手（每张一张 OnCardDrawn）→ 生成并广播首回合意图（OnIntentRevealed）
→ Turn=1，进入 PlayerMain → OnTurnStart(1) → 回复钩子 OnTurnStart
```

即：`Draw×N → Intent → Turn1`（BattleFlowTests 固化此顺序）。

**`EndTurn()` 内部时序**：

```
清空双方 ThisTurn 修饰 → 进入 EnemyTurn，重置敌方攻击旗
→ 依序执行当前意图列表（攻单位意图的目标已死 → 重定向打玩家；召唤/施法按规则执行）
→ 敌方单位依次攻击（随机合法目标，尊重玩家嘲讽；互殴同时结算）
→ 揭示下回合意图并广播 → Turn++，回到 PlayerMain
→ 全体单位 Turns 修饰递减 → 重置我方攻击旗 → OnTurnStart → 抽牌 → 回复钩子
```

任何一步终局立即返回并冻结（不会出现"死了还继续敌方回合"）。

## 五、核心规则的实现位置（策划案 → 代码对照）

| 规则（策划案 v2.1） | 实现要点 |
|---|---|
| 召唤费公式制 | `MonsterSleeve.SummonCost` = `max(0, round(Σ部位费 × 乘数, AwayFromZero) + 定值)`；**先乘算取整再加定值** |
| 攻血归属 | 底数=Σ身材槽部位攻血（**先求和**）× 卡套 `StatMultiplier`；卡套本体无任何数值 |
| 槽内卡不充能 | 部位卡 `Cost` 写死，召唤一次付清；充能阈值只存在于手牌效果卡 `EffectTier` |
| 手打面值无折扣 | `PlayCard` 按所选档位 `Cost` 扣点，不读任何卡套公式（有专门测试：站着 75% 卡套照样面值） |
| 卡槽四型 | `SlotType { Body, OnSummon, Continuous, OnLeave }`；部位卡声明槽型，`Install` 校验匹配 |
| 召唤前置 | `Validate()` 只做防御（缺身材槽抛异常）；合法性由整备阶段保证 |
| 充能档位 | `EffectTier[]` 按费用升序，任选付得起的档；低配/完全体只是数据差异 |
| 全局行动点 | `ActionEconomy` 跨回合不清零；`BattleResult.RemainingActionPoints` 供 run 层携带 |
| 回复框架 | `IRecoveryPolicy` 三钩子（见第八节），【预留】具体手段 |
| B+意图 | 敌方回合结束即生成并广播下回合意图——玩家永远先看谜面；四族意图见 `Intent.cs` |
| 嘲讽 | `Battlefield.AnyTaunt` 双方对称；只约束**攻击**目标（打脸也被拦），法术目标不受限 |
| 无召唤失调 | 召唤当回合即可攻击；每怪每回合 1 次（`AttackedThisTurn`，玩家回合开始重置我方、敌方回合开始重置敌方） |
| 场面无上限 | `BattleTuning.FieldUnitCap = 0` 默认无上限；>0 时双方同限（文档否决席位制，此字段仅为防守性配置） |
| 互殴同时结算 | 双方伤害一次落地、各发一次 `OnHpChanged`，再统一进死亡结算 |
| 死亡整包 | `ProcessDeaths` 循环（连锁防护上限 64）：标记死亡 → 移出场 → **整包进墓地** → 离场槽触发 → `OnUnitDied` → 光环重算 → 胜负检查，直到无新死亡 |
| 部位卡回收 | 默认全回收；`Consumable` 标记的部位随包销毁——体现在 `BattleResult` 两张清单 |
| 效果卡瞬间生命周期 | 打出→结算→消失，**不进墓地**（墓地只收怪兽整包） |
| PvE 不对称 | 敌方不走行动点：意图执行与敌方召唤均不扣费；敌方单位攻击是回合内自动行为 |

## 六、效果系统（数据驱动核心）

**一句话**：效果 = `EffectDef[]`（每组=目标选择 + 操作序列），解释器负责解析目标并逐操作执行。新卡=新数据，零代码改动。

**操作目录（EffectOp 七族）**：

| 操作 | 字段 | 备注 |
|---|---|---|
| `DamageOp` | Amount | 对单位或主战者 |
| `HealOp` | Amount | 上限夹紧，血量无变化不发事件 |
| `ModifyStatOp` | Stat/Amount/Duration | 攻或血上限；血上限增益同步抬血、减益夹紧 |
| `GrantKeywordOp` | Keyword/Duration | 关键词（现有 Taunt） |
| `GainPointsOp` | Amount | 仅玩家方生效（敌方无点数） |
| `DrawCardsOp` | Count | 仅玩家方 |
| `ConditionalOp` | Condition/ConditionTarget/Then/Else | 条件按求值对象求值（见上），分支可嵌套 |

**目标选择（TargetMode，相对效果来源阵营）**：`Chosen`（命令传入——技能主目标）/ `Self` / `AllEnemyUnits` / `AllFriendlyUnits` / `AllUnits` / `RandomEnemyUnit` / `EnemyHero` / `FriendlyHero` / **`Caster`（施法者=部位卡效果的所属单位 / 效果卡的施法主战者，GAS 的 Caster 概念）**。

**条件（ConditionDef）**：**`AttributeCompareCondition`**——属性（`生命/生命上限/攻击`）× 运算符（`>、≥、<、≤、=、≠`）× 比较值（固定数，或百分比——基准=比较对象自身生命上限，"半血以下"=生命 ≤ 上限×50%）。比较对象由 `ConditionalOp.ConditionTarget` 决定；主战者的攻击视为 0（主战者不攻击，既定规则）。参考 XH/GAS 的属性比较，剔除公式系统与即时制属性。

**条件求值对象（`ConditionalOp.ConditionTarget`，`ConditionTargetKind { Current, Caster, MainTarget }`，默认 Current）**：条件可独立于所在效果组选人——Current=被作用的目标（现状语义）、Caster=施法者、MainTarget=技能主目标（命令传入的 chosenTarget，召唤场景=召唤时透传的目标）。

**时长（ModifierDurationKind）**：`ThisTurn`（玩家回合结束清空）/ `Turns`（每玩家回合开始递减）/ `Battle`（永久）。**临时桶与光环桶分离**：命令/瞬间效果进临时桶按时长过期；常驻槽走光环桶，由 `RecomputeAuras` 全量重算（清空→逐存活单位重加），单位离场光环自动失效。光环只认 `ModifyStatOp`/`GrantKeywordOp`，其余操作忽略（配置侧保证）。

**触发时机**：部位卡效果按槽型路由——`OnSummon` 召唤时一次、`OnLeave` 死亡时一次、`Continuous` 光环化持续。部位卡还可 `GrantKeywords`（随召唤固化到单位 BaseKeywords）。

**导表落点**：配置 POCO 即未来 JSON 的形状（无参构造、公开字段，Newtonsoft 直接反序列化）。`Tests/SampleData.cs` 就是活样例，例如效果卡等价于：

```json
{ "Id": 301, "Name": "火球术", "Tiers": [
    { "Cost": 2, "Label": "低配",   "Effects": [ { "Target": "Chosen", "Ops": [ { "Amount": 3 } ] } ] },
    { "Cost": 4, "Label": "完全体", "Effects": [ { "Target": "Chosen", "Ops": [ { "Amount": 6 } ] } ] } ] }
```

**补丁纪律提醒**：加卡/改数值=改数据，补丁可行；**新增 EffectOp/Condition 类型或字段=表结构变化，必须出整合包**（板块划分文档的纪律）。

### 表现挂起（演出事件，v2 新增）

**问题**："怪兽入场动画结束后再选择敌人造成伤害"——演出进度与玩家输入驱动的时序，同步结算核心无法"等待"。

**方案（逻辑/演出解耦 + 全局事件投喂节拍）**：

1. `EffectDef.PlayAfterAnimation=true` 的效果组标记为"动画后"（技能编辑器"动画完成时"端口的编译产物）
2. `BattleSetup.DeferPresentationEvents`（默认 **false**）：false=挂起组**立即结算**——现有行为、全部测试、headless 零影响；true=挂起组进入 DeferredQueue（按单位挂起），等待事件放行
3. 表现层演出完成后 `GameEventBus.Send(new EntranceAnimDone { UnitId = id })`（全局事件系统，见《事件系统设计》）→ 战斗核心放行该单位挂起组、同步结算
4. "选一个敌人"：`SummonMonster(rosterIndex, chosenTargetId)` 透传目标（逻辑上召唤瞬间已确定）；演出顺序由表现层自由安排——玩家的体感是"动画完了才选人、才掉血"，核心从未等待
5. `GetSnapshot()` 暴露挂起组数量（UI 据此显示"演出进行中"）；BattleSession 订阅全局事件，Dispose 退订

**告诫**：延迟模式下忘发事件=召唤结算永远不完整（挂起计数可见，但要在表现层保证成对发送）。未来"死亡动画后触发离场槽"等演出时序【预留】走同一机制（新增 struct 事件即可）。

## 七、敌方 AI 与意图

`EnemyAI` 只做决策、不做状态变更（执行权在 `BattleSession.ExecuteIntent`）：

- **GenerateIntent**：随机数 0-99 分段 → 40% 攻玩家 / 30% 攻玩家某单位（随机预选）/ 20% 召唤（池中还有才可选）/ 10% 施法（池非空才可选）；玩家无单位时必为攻玩家；兜底攻玩家。
- **PickUnitAttackTarget**：玩家场上有嘲讽 → 必打嘲讽；否则玩家单位与玩家本人等概率随机。
- **谜面可读性**：攻单位意图在生成时预选目标并写进 `Describe()`；执行时目标已死 → 重定向打玩家本人（不吞伤害）。

意图调剂手段（"？"意图/隐藏一张/连击预告，策划案开放 #8）【预留】：加 `Intent` 子类 + 生成侧花样即可，契约不动。

## 八、行动点回复框架【预留】

战斗在三个点位回调策略，策略经 `ctx.Economy.Grant` 发点、经 `ctx` 读上下文：

| 钩子 | 时机 | 典型实现 |
|---|---|---|
| `OnTurnStart` | 每个玩家回合开始（含开局） | 每回合投骰回复（骰子走注入的 `Rng`） |
| `OnFriendlyAttackCompleted` | 我方单位攻击结算后 | 攻击一次回复 |
| `OnCardDiscarded` | 主动弃牌后 | 弃牌回复 |

`Recovery = null` 表示本场无回复。新增钩子点位（挡刀/离场等，策划案候选）= 在 `BattleSession` 对应动作处补一行回调 + 接口加方法。

## 九、随机性与复现

- 战斗内**一切**随机（洗牌、AI 意图与目标、随机目标效果）走构造时按 `BattleSetup.Seed` 创建的同一个 `Rng`——同种子 + 同命令序列 = 逐字节一致的重放（冒烟与 BattleFlowTests 双重固化）。
- `FixedDeckOrder`（配置 Id 序列）可绕过洗牌固定抽牌序，测试与演出重放用；未列全时剩余卡按组队顺序接在末尾（防御）。
- 复现 bug：记录种子 + 玩家命令序列，回放到出错帧即可。

## 十一、扩展指南（按改动类型查表）

| 要做什么 | 改哪里 | 改的是代码还是数据 |
|---|---|---|
| 新效果卡 / 新部位卡 / 新卡套 / 新敌人 | 配置 POCO 实例（未来=JSON 表） | **纯数据** |
| 新效果操作（如"召唤衍生物"） | `EffectOp` 子类 + `EffectInterpreter.ApplyOp` 加分支；若常驻槽可用再补 `RecomputeAuras` | 代码（=整合包） |
| 新条件（如"目标有嘲讽"） | `ConditionDef` 子类 + `EvalCondition` 加分支 | 代码（=整合包） |
| 新意图 / AI 策略调整 | `Intent` 子类 + `EnemyAI.GenerateIntent` + `ExecuteIntent` 加分支 | 代码 |
| 新回复手段 | 实现 `IRecoveryPolicy`（钩子已备）；缺点位再补钩子 | 代码+配置 |
| 接入 JSON 导表 | Loader 读表反序列化成配置 POCO → 组 `BattleSetup` → `new BattleSession(setup)`。核心侧零改动（构造注入边界已留好） | 代码（Loader 侧） |
| 接 UI | 订阅 `BattleEvents` + 命令方法 + `GetSnapshot`，按 UI 框架文档纪律 | 代码（UI 侧） |
| 新表现事件（如死亡动画结束放行离场演出） | GameEvents 程序集加 struct 事件 + 挂起/放行接入（见《事件系统设计》） | 代码 |

**已知边界与不做**（写代码时别绕进来）：常驻槽只认属性/关键词操作；光环重算为全量 O(n²)，小场面无碍；死亡连锁防护上限 64（防数据造环）；结算**默认**同步瞬时完成——表现挂起模式（DeferPresentationEvents=true）下节拍由表现层经全局事件投喂，忘发事件会卡住召唤结算（挂起计数可见）；静态事件跨战斗残留是 UI 文档已知告诫（重开局窗口自行重刷）；多分支效果的执行顺序由技能编辑器按"图左优先"编译定死；UI 交互、Loader/JSON/Mods、局外 Meta、整备编辑 API 均不在核心范围内。
